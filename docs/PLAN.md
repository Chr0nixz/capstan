# Capstan 项目方案

> 日期：2026-10-05（最后更新 2026-10-27）　状态：已确认
> 定位：个人使用、GitHub 开源（GPL-3.0-or-later）、Windows 优先并深度优化，之后再扩展到 macOS/Linux
> 名字：Capstan 是码头上收缆绳的绞盘，terminal 一词本身也有"码头"的意思

## 1. 定位与差异化

开源领域已经有不少同类项目：Tabby、electerm（Electron），WindTerm（Qt），还有 r-shell、shelo、shell360、Oryxis（Tauri/Rust）。它们大多走跨平台、功能堆叠的路线。

Capstan 的差异化：

- **Windows 一等公民**：新版 ConPTY、WSL 深度集成、Windows Hello、原生 Snap 布局和 Mica 效果、系统 SSH Agent
- **MobaXterm 的工作流，现代化的界面**：SSH 连上后 SFTP 侧栏自动跟随当前目录，同一条连接上开多个标签
- **轻量**：不捆绑 Chromium 或 Java；安装包体积目标以 M0 构建实测为准，区分下载体积和安装后体积，不把约 10MB 当作发布承诺
- **只做个人需要的**：不做团队协作、云同步、AI

说实话，个人项目最大的价值是完全按自己的习惯来做。差异化主要影响 README 怎么写，不必为了它强行加功能。

## 2. 技术架构

### 2.1 选型

| 层 | 选型 | 理由 |
|---|---|---|
| 外壳 | Tauri 2 + WebView2 | Win11 自带 WebView2，不用捆绑 |
| 异步运行时 | tokio | |
| SSH | `russh`（ring 后端）+ `russh-sftp` | 纯 Rust，异步，自带 Pageant/命名管道 agent 支持。ring 在 Windows 上编译比 aws-lc-rs 省事；RSA 私钥运算另用 `aws-lc-rs`（见决策记录） |
| 本地 PTY | `portable-pty` + 经核验的 ConPTY 运行时 | M0 验证加载、版本选择和系统回退；只有现成实现不满足明确需求时才评估自写封装及其兼容维护成本 |
| 加密 | `argon2`、`chacha20poly1305`、`zeroize`、`secrecy` | RustCrypto 生态 |
| 终端渲染 | xterm.js 5 + webgl、search、web-links、unicode11、fit 插件 | VS Code 也用它，兼容性经过验证，AI 也最熟悉 |
| 前端 | React 19 + TypeScript + Vite + Tailwind 4 + Radix UI | 命令面板 `cmdk`，分屏 `react-resizable-panels`，状态管理 Zustand |
| 包管理 | pnpm、cargo workspace | |

不自己写 GPU 渲染器。性能假设由 M0 的固定场景基准验证；IPC、终端解析、绘制和 WebView2 内存分别记录，不能预设瓶颈只在 IPC。

### 2.2 工程结构

```
capstan/
├── crates/
│   ├── capstan-vault/   # 加密库：密钥派生、加解密、原子写入、导入导出
│   ├── capstan-ssh/     # 连接池、shell/exec/sftp 通道、端口转发、agent、状态采集
│   ├── capstan-pty/     # 本地 shell 探测、ConPTY、WSL 枚举
│   └── capstan-terminal/ # 共享终端协议、字节流控、会话任务与状态
├── src-tauri/           # Tauri 命令、事件、窗口，只负责粘合
├── ui/                  # React 前端
└── docs/
```

所有领域 crate 都不依赖 Tauri。`capstan-terminal` 不依赖 PTY 或 SSH；本地适配器依赖共享终端契约，SSH 接入时复用相同的流控与帧协议，不依赖 `capstan-pty`。`src-tauri` 保留命令、Channel 和窗口适配。前端显示组件、会话控制器与类型化 IPC 分开，Zustand 只保存可序列化布局和会话状态。

### 2.3 终端数据流

```
PTY / SSH 通道 ─读取─> 有界合并器（16ms 或 64KB）─Tauri Channel 原始二进制─> xterm.write()
      ^                                                                      │
      └── 未确认积压 > 1MB 暂停读取，< 256KB 恢复 <── 按字节数 ACK ───────────┘
键盘输入：xterm.onData ─invoke─> 有界输入队列 ─> PTY / SSH 通道
```

- 图中的合并间隔、帧大小和暂停/恢复阈值是当前默认值，可按实测调整；调整时在决策记录留痕。
- 每个可见终端有独立的有界队列；统计 Rust 队列、IPC 在途和前端待处理字节，不能只统计其中一段。禁止把终端字节流转成 JSON 数组或 Base64。
- 前端在 `xterm.write` 完成回调后按实际处理字节数 ACK；传输错误、终端卸载或窗口关闭时取消对应流并释放队列。
- M0 验证 Channel 的原始二进制路径、顺序、背压和取消语义，并记录数据完整性、吞吐、输入响应和峰值内存。
- 正常 EOF 停止接收并排空已接受输出；取消允许丢弃待处理输出，但关闭须等待关联任务和子进程回收。字节预算在入队时登记，覆盖待合并与已发送未确认的数据，ACK 不重复计算前端待处理字节。输入发送结果不确定时丢弃排队输入，不自动重放。

### 2.4 连接模型

- 每个兼容的连接配置最多复用一条 SSH 连接，上面挂多个通道：N 个 shell、最多 3 个 SFTP 子系统（含共享浏览主通道）、1 个状态采集、M 个隧道。复用键至少包含目标地址/端口、用户名、认证身份和跳板/代理路径；安全策略不兼容的配置不得合并。
- 最后一个通道关闭后，连接保留 30 秒再断开，方便马上重开
- 连接生命周期显式区分连接中、认证中、已连接、重连中和已关闭状态。
- 重连不会恢复远端 shell 进程，也不会自动重放键盘输入或任意命令。旧 shell 标记为已结束并保留屏幕回滚；SFTP 通道可重开；自动启动的隧道按配置重建；状态采集重新开始。传输任务只有在目标文件和偏移验证通过时才续传。

### 2.5 数据存储

安装版数据放在 `%APPDATA%\Capstan\`。便携版使用 exe 旁可写的数据目录；目录不可写时明确报错，不静默改存其他位置：

| 文件 | 内容 | 是否加密 |
|---|---|---|
| `settings.json` | 界面偏好、字体、主题、快捷键 | 否 |
| `vault.cvault` | 主机、分组、凭据、片段、隧道规则 | 整个文件加密 |
| 信任记录 | SSH 主机指纹、算法和首次信任时间 | 存在加密 Vault 内 |

主机名和 IP 也放在加密库里，这样别人拿到文件也看不出你连过哪些服务器。代价是看主机列表前必须先解锁，不过本地终端不需要解锁就能用。

SSH 主机指纹保存在加密 Vault 内，避免应用自己的明文信任文件暴露目标主机。可选支持从系统 `~/.ssh/known_hosts` 只读导入已信任条目；导入时校验 OpenSSH 格式并显示将导入的主机和指纹，不修改原文件，也不默默把系统文件的信任范围扩大到通配条目或证书颁发机构。

Vault 文件使用带 magic 和 schema 版本的封装格式。封装至少记录 KDF 标识及参数、随机 salt、DEK 包装 nonce/ciphertext、数据 nonce/ciphertext；认证数据绑定格式版本和 KDF 元数据。所有 nonce 使用密码学安全随机数且在同一密钥下不得复用。KDF 参数可随格式版本升级，解锁时按文件中记录的参数派生密钥。

写入流程为同目录临时文件、写入并 flush、同步文件内容、原子替换，再同步目录（平台支持时）；启动时识别并恢复/清理未完成写入。备份保留最近 3 个经过格式和认证校验的加密版本。加密认证能检测篡改，但不提供防回滚保证；备份恢复可能恢复到较旧的数据版本。

## 4. 功能规格

### 4.1 布局（混合式）

```
┌──┬───────────┬─────────────────────────────────────┐
│▣ │ 🔍 搜索    │ [web-01 ×] [db-01 ×] [PowerShell ×] [+] │
│📁│ ★ 收藏     ├──────────────────┬──────────────────┤
│⇄ │ ▾ 生产     │ $ top            │ $ tail -f app.log│
│⌘ │   web-01 ● │                  │                  │
│  │   db-01    │                  │                  │
│  │ ▾ 测试     ├──────────────────┴──────────────────┤
│  │ ▸ 本地     │ SFTP  /var/log  [跟随 ✓] ↑ ↓ ⟳       │
│⚙ │           │ 📁 nginx  📄 app.log 2.1MB  …        │
├──┴───────────┴─────────────────────────────────────┤
│ ● web-01  CPU 12%  MEM 3.1/8G  DISK 41%  ↓1.2M ↑80K │
└────────────────────────────────────────────────────┘
```

- 左侧活动栏切换：会话 / SFTP / 隧道 / 片段 / 设置。侧栏可以折叠
- SFTP 面板可以停靠在下方或右侧，也可以折叠
- 新标签页显示最近和收藏的主机卡片，以及本地 Shell 入口
- 命令面板（Ctrl+Shift+P）：搜索并连接主机、运行片段、切换主题、执行任何操作

### 4.2 会话管理与 SSH

- 树形分组，支持拖拽、收藏、模糊搜索（名称、地址、标签）
- 每台主机的配置：地址、端口、用户名、认证方式、默认目录、启动命令、编码、终端配色（生产环境可以设成红色背景提醒自己）、生产标记（分组上设置时向其中的主机和子分组继承）
- 认证方式：密码；私钥（OpenSSH / PEM 格式，可以导入加密库，也可以只引用文件路径）；SSH Agent
- 首次连接弹窗显示指纹让你确认；指纹变化时直接阻断，并显示新旧对比
- Agent 转发默认关闭，每台主机单独开启

### 4.3 加密库

- 主密码 → Argon2id → 密钥加密密钥（KEK）。内存、迭代和并行参数由版本化文件头记录；默认参数和允许范围已在 M1 确定（见 [VAULT-FORMAT.md](VAULT-FORMAT.md)），文件头参数超出范围时拒绝解锁，避免恶意文件头造成资源耗尽
- KEK 包裹一个随机生成的数据密钥（DEK），库内容用 DEK 以 XChaCha20-Poly1305 加密
- 改主密码只需要重新包裹 DEK；Windows Hello 可作为本机可选的 DEK 解锁方式，主密码始终可用
- Vault schema 有明确版本和迁移测试；损坏或未知版本不得覆盖原文件
- 空闲自动锁定（默认 30 分钟，可以关闭）。Vault 锁定默认不主动中断已有连接，但禁止新建需要凭据的连接；应用管理的 DEK、KEK 和凭据临时缓冲区尽力清零。Vault 锁定不等同于锁定 Windows 会话，活动终端仍可能显示和交互；另提供“锁定时断开连接”选项
- 导出：用单独的口令加密成 `.cbak` 文件。导入时可以选择合并或覆盖，冲突时提示

### 4.4 本地终端

- 自动探测 Windows PowerShell 5.1、PowerShell 7、所有 WSL 发行版；也可以手动添加自定义 Shell
- 本地标签不显示 SFTP 面板

### 4.5 SFTP 侧栏

- SSH 连接后自动打开，跟着当前标签切换
- **跟随目录**：解析 xterm 已解析的 OSC 7，不从原始终端字节流另行猜测。校验 URI scheme、主机和路径，只接受当前会话对应的远程主机；拒绝越界或格式错误路径。Shell 集成首版支持 Linux Bash/Zsh，只修改用户明确选择的文件，使用可识别标记、幂等安装和安全卸载；先备份并检查文件类型，失败时保留原文件。不安装时 SFTP 可手动输入路径
- **传输队列**：拖拽上传下载文件和文件夹；默认 3 个任务并发，每个任务内部多个请求流水线；对可 seek 的常规文件支持断点续传，重试前校验远程目标、文件大小和偏移；冲突时询问覆盖/改名/跳过。显示速度和剩余时间
- **远程编辑**：双击文本文件，下载到随机临时目录，用设置的编辑器打开。检测保存后自动回传；上传到远程同目录临时文件并在支持时原子 rename。回传前比较捕获的文件属性（至少大小和修改时间），变化时提示冲突；这只能检测常见并发修改，不能保证消除检查与替换之间的竞态。限制文件大小并拒绝目录和不支持的文件类型；退出或启动清理残留临时文件
- 常规操作：新建、重命名、删除（需确认）、修改权限、复制路径、显示隐藏文件

### 4.6 分屏与广播

- 窗格可以任意嵌套拆分、拖拽调整大小；标签可以拖拽排序
- 广播输入：在标签内勾选目标窗格，参与广播的窗格显示琥珀色虚线边框和“广播”标记（红色只表示生产主机和失败）。同一组目标第一次发送换行前确认一次，之后单行命令直接发送，直到目标选择变化；一次发送多行内容（粘贴或片段）每次都要确认

### 4.7 终端体验

- Ctrl+Shift+F 搜索，支持正则和大小写敏感；链接可点击，非 http(s) 链接打开前要确认
- **断线重连**：keepalive 检测和系统唤醒事件都会触发重连，按指数退避重试；一轮重试用尽后，网络变化或唤醒会重新开始一轮。重连后插入一行分隔提示，之前的输出保留。远程正在运行的进程无法恢复，这种情况建议在服务器上用 tmux
- 右键菜单：复制、粘贴、选中即复制（可选）、清屏

### 4.8 服务器状态栏

- 连接后先跑一次 `uname`，只对 Linux 启用
- 一个长驻 exec 通道，每 3 秒循环读取 `/proc/stat`、`/proc/meminfo`、`/proc/loadavg`、`/proc/net/dev` 和 `df`。窗口最小化时暂停
- 显示 CPU、内存、磁盘、网速，点击展开详情

### 4.9 端口转发

- 支持本地（-L）、远程（-R）、动态 SOCKS5（-D）三种
- 可以设置随连接自动启动，也可以手动开关；手动停止的自动隧道保持停止，直到再次手动启动或应用重启
- 隧道面板显示状态、连接数、流量；本地端口被占用时给出明确报错

### 4.10 命令片段

- 支持 `{{变量}}` 和 `{{变量:默认值}}`，发送前弹窗填写；不符合变量格式的 `{{…}}` 按原样发送
- 发到当前窗格或广播；可以选择是否自动加回车
- 分组管理，命令面板里可以搜索

### 4.11 外观

- 深色为主，跟随系统切换浅色
- 内置几套终端配色，可以导入 Windows Terminal 和 iTerm2 的配色文件
- 界面中英双语，默认跟随系统语言

## 5. 安全设计

| 原则 | 做法 |
|---|---|
| 远程认证凭据不进入前端 | SSH 密码和私钥只在 Rust 侧解密，前端只传主机 ID 或凭据 ID；Vault 主密码只经专用解锁流程提交给 Rust，不进入持久化前端状态、日志或通用事件。使用 `secrecy`/`zeroize` 管理应用拥有的缓冲区；不承诺清除第三方库或操作系统内部副本 |
| Tauri 权限最小化 | 只开放自己写的命令，不启用通用的 shell、fs 插件；严格的 CSP，不加载任何远程内容 |
| 主机指纹 | 首次信任，之后严格校验，变化时阻断 |
| 终端转义序列 | 远程写剪贴板（OSC 52）默认询问，读剪贴板一律禁止 |
| 粘贴保护 | 多行粘贴弹窗确认，支持 bracketed paste |
| 临时文件 | 远程编辑的文件放在随机子目录里，关闭就删，启动时清理残留 |
| 日志 | 不记录密码、私钥和终端内容 |
| 更新 | 暂不做 Windows Authenticode 安装包签名。Tauri 自动更新使用独立的更新包签名密钥；私钥只存于受限 CI Secret，公钥随应用发布。未配置并验证更新包签名时，不启用自动更新 |
| 依赖 | CI 里跑 `cargo deny` 检查漏洞和许可证，Dependabot 自动提升级 PR |

安全边界：Vault 加密主要保护设备关闭或应用退出后的离线数据，不防已解锁会话中的本机恶意代码、管理员权限攻击或内存转储。应用锁定时继续运行的 SSH 会话仍有活动终端内容；用户可选择锁定时断开所有连接。所有 Tauri 命令逐项定义调用来源、参数范围和能力，不向前端暴露任意文件系统或进程执行接口。

## 6. 测试方案（不依赖 Docker）

## 7. 开源与发布

- **许可证**：GPL-3.0-or-later。任何人分发修改版或基于它的产品，都必须以 GPL 公开源码。没选 AGPL，因为 AGPL 多出来的条款只约束"通过网络提供服务"的场景，对桌面应用没有实际作用
- **依赖许可证**：只允许与 GPL-3.0 兼容的许可证（MIT、Apache-2.0、BSD、ISC、Zlib、MPL-2.0 等），由 `cargo deny` 和前端的许可证检查强制执行。GPL-2.0-only 的依赖不能用
- 捆绑的 ConPTY 来自 microsoft/terminal 仓库；在锁定具体 NuGet 包及版本后核实仓库许可证、包内每个二进制的再分发条款和签名，并在 `THIRD_PARTY_NOTICES` 里列出。未完成核验前不发布捆绑文件
- **CI/CD**：GitHub Actions 在分支推送和面向 `main` 的 PR 上运行 Windows x64 和 Ubuntu OpenSSH 检查。`main` 手动演练提供安装包、便携包和 SHA-256。维护者推送与源码版本一致且指向 `main` 历史的 `vX.Y.Z` 后，同一套检查通过即自动发布到 Releases。
- **自动更新**：Tauri updater + GitHub Releases；仅在更新包签名密钥、验证流程和恢复说明就绪后启用
- **安装包签名**：首批版本暂不做 Windows Authenticode 签名；用户可能看到 SmartScreen 警告。后续是否申请开源代码签名证书另行决策。此项不取消自动更新所需的更新包密码学签名
- **仓库文档**：中英文 README、CONTRIBUTING、SECURITY.md（漏洞报告方式）、CHANGELOG
- **提交规范**：Conventional Commits，方便自动生成更新日志

## 9. 主要风险

| 风险 | 应对 |
|---|---|
| russh-sftp 的性能或成熟度不够 | M2 先做基准测试，不行就在 russh 的通道上自己实现 SFTP 流水线 |
| xterm.js 在 WebView2 里的中文输入法表现 | M0 第一周就验证。有问题优先给 xterm.js 打补丁或提 PR |
| portable-pty 无法安全加载捆绑的 ConPTY | M0 先做加载、版本和回退验证；只有确认缺少所需能力后才评估自写封装，并单独估算 Windows API、资源释放和兼容测试成本 |
| WebView2 的内存基线 | 实际会比宣传的数字高，M0 记录真实值，不承诺具体数字 |
| ConPTY NuGet 文件的许可或分发条件不清楚 | 固定具体包版本并核验包内二进制许可、签名和发布渠道；未确认前不随安装包分发 |
| Tauri Channel 无法达到原始二进制和背压要求 | M0 技术门先验证真实端到端行为；若能力不满足，先调整 IPC 传输实现，不退化为 JSON 数组或 Base64 |
| 远程编辑或传输覆盖并发修改 | 采用临时文件、属性检查和明确冲突操作；说明属性比较存在竞态，避免声称无损冲突检测 |
| 个人项目做着做着失去动力 | M1 就做到能日常用，之后每个里程碑都能马上用上；流程保持轻量，不让验收流程拖住可用版本 |
