## 1. 目标与范围

M4 把 Capstan 打磨成顺手的 Windows 日常工具：SSH 标签能看到服务器负载，终端有常用右键操作和自定义配色，应用融入任务栏、通知、资源管理器和全局热键，Vault 可用 Windows Hello 解锁，新版本能安全自动更新。新功能不得削弱已有的连接、传输和 Vault 数据安全。

| 功能 | 依据 | 要点 |
| --- | --- | --- |
| 服务器状态栏 | §4.8 | Linux 主机的 CPU、内存、磁盘、网速；每条连接一个长驻 exec 通道，每 3 秒采样，最小化时暂停，点击展开详情 |
| 终端右键菜单 | §4.7 | 复制、粘贴、选中即复制（可选）、清屏 |
| 主题导入 | §4.11 | 导入 Windows Terminal 和 iTerm2 配色，可用于主机配置和命令面板 |
| 单实例与系统集成 | §3 | 单实例运行；资源管理器右键“在此处打开 Capstan”；`ssh://` 链接关联 |
| 任务栏 | §3 | 任务栏图标显示传输进度；跳转列表显示最近会话 |
| 系统通知 | §3 | 大文件传输完成、连接断开时弹 Toast |
| Quake 模式 | §3 | 全局热键呼出或隐藏窗口 |
| Windows Hello | §3、§4.3 | 本机可选的 DEK 解锁方式，主密码始终可用 |
| 自动更新 | §5、§7 | Tauri updater + GitHub Releases；验签，失败不破坏现有安装 |
| 可访问性检查 | §8 | Win11 高对比度、键盘操作、reduced-motion |

PLAN §8 的“右键菜单”按 §4.7 的终端右键菜单实施；资源管理器右键属于 §3 的系统集成，也在 M4 完成。

不包括：Authenticode 签名、托盘图标、Win11 新式顶层右键菜单（需要包标识，本阶段只做“显示更多选项”里的经典菜单）、扩充内置配色、界面主题、新的 SSH 功能、ARM64、macOS/Linux。M4 完成不等于授权发布、打 tag、提交或推送。

## 4. 接口契约

名称可以贴合现有代码，在 M4-1 开头写进 fixture 固定，后续阶段新增 DTO 时同步补进 fixture；以下边界和行为不得改变。

### 4.1 服务器状态栏

- **exec 通道**：`capstan-ssh` 新增在已有连接上打开 exec 通道的 API，命令参数只接受 `&'static str`，不能拼接主机、路径或用户输入；提供有界的 stdout 读取、stdin 写入和退出状态。
- **采集脚本**：固定的 POSIX `sh` 脚本，兼容 bash、dash 和 busybox；登录 shell 是 fish 这类非 POSIX shell 时也要能跑（例如 exec 只发送 `sh`，脚本经 stdin 写入）。脚本先输出 `uname -s`，不是 `Linux` 就退出；之后每读到一行 stdin 采一次样，输出带版本标记的帧，内含 `/proc/stat`、`/proc/meminfo`、`/proc/loadavg`、`/proc/net/dev` 和 `df -P -k`。暂停就是不再发送 tick，通道保留。
- **解析**：在 Rust 侧完成。单帧 ≤ 64 KiB，网卡和挂载点各 ≤ 64 项，CPU 行 ≤ 1024；超限记 `status_limit`，不无限缓冲。CPU 和网速由相邻两帧的差值计算，计数回绕或重置时该帧不出速率。网速汇总除 `lo` 外的网卡。
- **快照 DTO**：`ServerStatusSnapshot { connection_id, generation, state, error_code?, sampled_at, cpu_percent?, load?: [f32; 3], memory?: { total, available }, disk?: { mount, total, used }, network?: { rx_per_sec, tx_per_sec }, details? }`。`state` 取 `probing | running | paused | unsupported | unavailable`；摘要里的磁盘取 `/`；字节数沿用现有 `ExactU64` 约定；详情（各挂载点、各网卡）有数量上限。
- **调度**：每条连接最多一个采集器。只有当前显示的 SSH 连接按 3 秒采样；其他连接、窗口最小化或被 Quake 隐藏时暂停。前端只报告当前显示的 `ConnectionId`，最小化和隐藏状态由 Rust 从窗口事件取得。
- **生命周期**：连接的第一个 shell 就绪后启动。采集通道不单独延长连接寿命：最后一个 shell、SFTP 或隧道关闭时先关采集器，30 秒空闲保留规则不变。重连产生新代次和新采集器，旧代次的快照一律丢弃。
- **失败隔离**：通道打开被拒（含服务器 `MaxSessions` 用尽）、脚本失败或解析错误时，只让状态栏进入 `unavailable`，不影响 shell、SFTP 和隧道，也不触发重连。同一代次最多自动重开 1 次，之后等重连或用户点击重试。错误码：`status_unsupported`、`status_rejected`、`status_parse`、`status_limit`、`status_closed`。
- **界面**：底部全宽状态栏，显示主机名、CPU、内存、磁盘和上下行速率；点击或按 Enter 展开详情，Esc 收起。本地标签不显示状态栏。

### 4.2 终端右键菜单

- 菜单项：复制（有选区时可用）、粘贴、清屏、选中即复制开关。`Shift+F10` 或菜单键也能打开；方向键选择，Esc 关闭并把焦点还给终端。沿用 SFTP 面板的菜单实现，不新增 UI 依赖。
- 远端程序开启鼠标上报时（如 vim `mouse=a`、htop），右键交给远端；`Shift+右键` 始终打开菜单。
- 粘贴走现有路径：bracketed paste、多行确认、广播目标和确认规则都不变。
- 清屏只清本地 xterm 的屏幕和回滚，不向远端发送任何字节。
- 选中即复制默认关闭，存在 `settings.json`。它只写剪贴板，不读剪贴板；远程 OSC 52 策略不变。

### 4.3 主题导入

- 入口是 Rust 命令：原生文件选择器（`*.json`、`*.itermcolors`）→ Rust 读取（≤ 1 MiB）并解析 → 前端只收到校验后的预览 → 用户确认后保存。文件路径和原始内容不进入 WebView。
- Windows Terminal：至少支持单个配色对象和含 `schemes` 数组的片段；字段为 `name`、`foreground`、`background`、`cursorColor`、`selectionBackground` 和 16 个 ANSI 色名（`black` … `brightWhite`）。完整的 `settings.json` 若含注释而解析器不支持，给出明确提示。
- iTerm2：XML plist，读取 `Ansi 0`–`Ansi 15 Color`、`Foreground Color`、`Background Color`、`Cursor Color`、`Selection Color`，0–1 分量按 sRGB 换算。XML 解析不得处理 DTD 或外部实体。
- 校验：前景、背景和 16 个 ANSI 色必需，光标和选区缺失时用默认值。颜色统一成 `#rrggbb`，丢弃 alpha。名称去掉控制字符，≤ 64 字符；重名时加序号，不覆盖内置主题。
- DTO：`TerminalThemeDefinition { id, name, source: "windows_terminal" | "iterm2", foreground, background, cursor, selection_background, ansi: [16] }`。内置 ID 仍是 `graphite`、`light`，导入主题 ID 为 `custom:<uuid>`。
- 存储按 D8。主机记录的 `theme` 字段保存主题 ID，找不到时按 `graphite` 显示，不改写 Vault。导入主题可重命名、删除。
- 前端 `TerminalTheme` 从字面量联合扩展为主题 ID；`terminalPalette` 根据主题定义生成调色板；命令面板列出所有主题。

### 4.4 单实例与启动请求

- 只接受以下参数；其他参数忽略，按无参数处理：
  - 无参数：启动应用，或聚焦已有窗口（包括被 Quake 隐藏的窗口）。
  - `--local [--shell <profile-id>] [--cwd <dir>]`：新建本地终端。
  - `--host <uuid>`：打开已保存的主机，供跳转列表使用。
  - 单个 `ssh://` URL。
- 解析是 `capstan-core` 里的纯函数：最多 8 个参数，单个 ≤ 4096 字符；解析失败或超限时按无参数处理。`--cwd` 只接受已存在的盘符绝对路径或 UNC 目录，拒绝相对路径、设备命名空间（`\\.\`、`\\?\`）、ADS 和不存在的目录；WSL 用不了该目录时改用默认目录并提示。
- 单实例：第二个进程只把原始参数转发给第一个进程，然后退出；第一个进程重新解析，不信任转发方的解析结果。待处理请求最多 8 个。需要 Vault 的请求在锁定时先请求解锁，用户取消解锁就丢弃。
- 便携版和安装版数据目录不同，不得互相转发（单实例锁名要区分数据目录）。官方插件做不到时，在核验中改用命名管道实现，或请维护者决定。
- 路径留在 Rust：前端收到 `LaunchRequestView { request_id, kind, display }`，再用 `request_id` 调用打开命令，不回传路径。

### 4.5 `ssh://` 链接

- 解析 `ssh://[user@]host[:port][/]`，支持方括号 IPv6。百分号解码后拒绝控制字符；用户名 ≤ 256、主机 ≤ 253 字符，端口 1–65535。路径、查询和 `;fingerprint=` 等连接参数一律不用：URL 里的指纹不得建立或扩大信任。
- 连接前一律确认，并显示解析出的用户、主机和端口。地址、端口、用户名都与已保存主机一致时，确认后用该主机连接，多台一致时让用户选择；没有一致的主机时，打开预填的新建主机表单，用户选好凭据并保存后才连接。主机指纹流程不变。

### 4.6 资源管理器右键与注册表

- 只有安装版写注册表，全部在 HKCU，不需要管理员。目录右键写 `Software\Classes\Directory\shell\Capstan` 和 `Directory\Background\shell\Capstan`，命令为 `"<安装目录>\<exe>" --local --cwd "%V"`；`ssh` 关联按 D2。通过 Tauri NSIS hooks 写入。
- 卸载只删除自己写入的键；升级不重复写入。便携版不写注册表。
- Win11 下菜单出现在“显示更多选项”里。

### 4.7 跳转列表

- 任务：每个检测到的本地 Shell 配置一项（≤ 6），参数为 `--local --shell <id>`。
- 最近主机（按 D1 开启后）：≤ 10 项，参数为 `--host <uuid>`，只显示主机显示名。连接成功后更新；删除主机、覆盖导入、关闭该选项或点击“清除”时移除。
- 原生实现放在 `vendor/capstan-native-windows`；AppUserModelID 与安装器快捷方式一致。核验便携版的行为，不可靠就不在便携版写跳转列表。

### 4.8 任务栏进度

- `capstan-core` 里的纯函数把传输快照聚合成 `{ state: none | normal | indeterminate | paused | error, percent }`：没有活动任务为 none；总量未知（如目录扫描中）为 indeterminate；剩余任务都暂停或等待重连为 paused；有失败或待决冲突为 error，直到用户在队列中处理；其余按当前批次的已完成字节/总字节计算 percent。
- `src-tauri` 用 Tauri 窗口的进度条 API 设置，最多每秒 4 次，值没变就不调用。不新增前端权限。

### 4.9 系统通知

- 判定在 core。传输按 D3 的阈值。连接断开指已连接状态转为重连中或失败，且不是用户关闭、锁库、锁库断开或取消造成的；每个连接代次最多通知一次，重试过程中不再通知。主窗口在前台时不通知；10 秒内的多条合并成一条摘要。
- 内容按 D1，绝不包含终端内容、远程路径或凭据。设置里可以关闭通知，默认开启。
- 从 Rust 发送，不给前端通知权限。便携版等没有 AUMID 的情况，发送失败只记录错误码，静默降级。

### 4.10 Quake 模式

- 设置项：开关（默认关）、热键、高度百分比（按 D4）。热键字符串在 Rust 校验：必须含 Ctrl、Alt 或 Win；拒绝单键、只带 Shift 的组合，以及只带 Ctrl 的字母键（避免与 `Ctrl+C` 等终端输入冲突）。
- 在 Rust 注册热键；注册失败（如已被占用）时设置页给出明确错误，功能保持关闭。修改热键时先注册新键、再注销旧键，失败则保留旧键。
- 呼出：窗口隐藏或不在前台时，移到光标所在显示器顶部，显示并聚焦当前窗格；已在前台时隐藏（不是最小化）。关闭 Quake 模式后恢复原来的窗口位置和大小。
- 隐藏不关闭会话、不丢失回滚；状态采集暂停；WebGL 按现有可见性规则处理。reduced-motion 下不做窗口动画。

### 4.11 Windows Hello

- **Hello API**：采用 NCrypt 的 Microsoft Passport KSP，使用 RSA-2048 非导出解密密钥。解密前要求新的用户手势，并拒绝允许静默私钥操作的提供者；真实解密与每次手势仍须设备验收。Hello 必须参与密钥解封，不使用 `UserConsentVerifier` 加 DPAPI 的界面确认方案。
- **sidecar**：数据目录内的 `vault-hello.cwh`，≤ 1024 字节，不能匹配 Vault 恢复扫描的 backup/pending 模式。包含 magic、版本、Vault 文件标识（头部 12–27 字节）、Hello 密钥名、KSP 保护的随机包裹密钥、随机 nonce、XChaCha20-Poly1305 包裹的 DEK，以及 D9 的最多两个加密 KEK slot。写入用临时文件加原子替换。`.cbak` 导出和 Vault 备份轮换都不包含它，具体格式见 [VAULT-FORMAT](../VAULT-FORMAT.md#optional-windows-hello-sidecar)。
- **启用**：Vault 已解锁，按 D5 重新验证主密码，Hello 验证通过后写入 sidecar。
- **解锁**：Hello 验证 → 解出 DEK 和匹配的 KEK → 认证主密码包裹的 DEK 与 Vault 载荷，再发布可写 Vault。任一步失败都回到主密码解锁，不修改 Vault。错误码：`hello_unavailable`、`hello_canceled`、`hello_key_missing`、`hello_mismatch`、`hello_data`。
- **修改主密码**：先原子写入含旧、新 KEK slot 的 sidecar，再替换 Vault；中断在替换前后均有匹配 slot。DEK 和载荷密文不变。
- **失效**：sidecar 与 Vault 文件标识不符、DEK 认证失败或 Hello 密钥不存在（如便携版换了电脑）时视为失效；只在主密码解锁成功后提示并删除失效的 sidecar。
- **停用**：删除 sidecar 和 Hello 密钥。
- 平台无关的格式和密码学放在 `capstan-vault`，通过 trait 注入 Hello 提供者，测试用运行时生成密钥的假提供者；FFI 放在 `vendor/capstan-native-windows`。包裹密钥、DEK、KEK 和解密缓冲区用 `Zeroizing` 管理。
- 自动锁定、锁定时断开和主密码流程不变。

### 4.12 自动更新

- 在 Rust 侧使用 `tauri-plugin-updater`，只通过自定义命令暴露“检查”“下载并安装”“取消”，不给前端插件权限。端点固定为 `https://github.com/Chr0nixz/capstan/releases/latest/download/latest.json`，公钥写在 `tauri.conf.json`。未配置公钥的构建里，更新功能显示为不可用。
- **检查**：版本必须高于当前版本（拒绝降级和同版本），平台为 `windows-x86_64`，下载地址必须在本仓库 Releases 下，安装包 ≤ 200 MiB。发布说明按纯文本显示。
- **安装**：用户确认；有活动会话或传输时额外提示。下载到临时目录 → 验签 → 交给 NSIS（passive 模式）→ 应用走正常退出流程（写完设置、保存传输恢复记录）。
- **失败**：网络错误、签名缺失或错误、换了密钥、包被篡改、版本不符、超限、磁盘不足、取消或安装器启动失败时，删除临时文件；现有安装、`settings.json`、Vault 和恢复文件都不变，可以重试。更新流程从不写 Vault。
- **安装失败回滚**：核验 Tauri NSIS 更新中途失败后的状态。若不能保证旧版本可启动，就在 NSIS hook 里先备份安装目录，失败时还原。
- **发布流水线**：验证作业照常构建未签名包；只有受 GitHub Environment 保护的 tag 发布作业能读取签名私钥，对已验证的安装包运行 `tauri signer sign`，生成 `.sig` 和 `latest.json`，校验后上传。PR 和分支构建拿不到私钥。`scripts/release.py` 上传前用公钥验证签名。
- **文档**：新建 `docs/UPDATES.md`，写明更新流程、密钥保管、私钥泄露或丢失时如何轮换（发布一个需手动安装、带新公钥的版本），以及更新失败后的手动恢复方法。

## 5. 不变量

- 领域逻辑放在 Rust crate；`crates/*` 不依赖 Tauri。`src-tauri` 只做参数和权限检查、DTO 转换、窗口事件和插件接线。
- 工作区禁止 `unsafe`。Windows FFI（跳转列表、Hello、Toast 等需要时）只放在 `vendor/capstan-native-windows`，并更新它的 `CAPSTAN_PATCH.md`。
- 新增 Tauri 插件只从 Rust 调用。`src-tauri/capabilities/default.json` 不新增插件权限，CSP 不变，不启用通用 shell、fs 或 opener 插件；新命令只接受 `main` 窗口。
- 状态采集是同一 SSH 连接上的通道，不另建 TCP 连接，不解析隐藏 shell 的输出。采集失败不影响其他通道，也不触发重连。
- 终端字节流、ACK/背压、输入队列和广播规则不变；右键菜单、清屏和主题切换不改变 session，也不向远端发送未经用户操作的字节。
- 外部输入一律视为不可信：启动参数、转发的参数、`ssh://` URL、配色文件、更新清单和发布说明都在 Rust 解析并设上限；`ssh://` 和 `--host` 都不能绕过连接确认和主机指纹流程。
- 前端不接触本地路径、文件内容或凭据，只拿到 request ID、主题预览和状态快照。
- Vault 加密格式不变；Hello sidecar 是可删除的附加文件，删除或损坏后只需改用主密码。任何 Hello、更新或注册表失败都不得修改 Vault、`settings.json` 或已安装文件。
- 跳转列表、通知、注册表和任务栏里的主机信息按 D1 处理；任何系统可见表面都不出现地址、用户名、远程路径、终端内容或凭据。
- 注册表只写 HKCU，卸载清理干净；便携版不写注册表，也不改其他应用的关联。
- 签名私钥只存在于受保护的 CI secret 中；测试密钥只在测试运行时生成，不入库。
- 所有可见文字走 `zh-CN` 和 `en` i18n；日志不得包含凭据、终端内容、状态帧原文、配色文件内容或启动参数中的路径。
- 新 UI 支持键盘操作，在 forced-colors 下可辨认，并遵守 `prefers-reduced-motion`。

## 8. 验收标准

每项功能单独验收：

1. **状态栏**：连接 Linux 主机后 3–6 秒内显示 CPU、内存、磁盘和网速，之后每 3 秒刷新；详情可展开、收起。非 Linux 主机显示“不支持”且不报错。最小化或隐藏后不再采样，恢复后继续。采集失败不影响终端和 SFTP。重连后重新采集，不显示旧代次数据。
2. **右键菜单**：复制、粘贴、清屏、选中即复制可用；多行粘贴和广播粘贴仍按原规则确认；清屏不向远端发送字节；vim/htop 开启鼠标时右键交给远端，`Shift+右键` 打开菜单。
3. **主题导入**：能导入 Windows Terminal 和 iTerm2 配色，确认前可预览；导入后可用于主机配置和命令面板，重启后保留；删除主题后使用它的主机回退为默认配色；坏文件给出明确错误，不保存任何内容。
4. **单实例**：再次启动只聚焦已有窗口或执行转发的请求；便携版和安装版可以同时运行。
5. **资源管理器右键**：在目录或目录空白处选“在此处打开 Capstan”，在该目录打开本地终端；卸载后菜单消失；便携版不写注册表。
6. **`ssh://`**：点击链接后先显示确认；匹配已保存主机时用其凭据连接；未知主机打开预填表单；URL 中的指纹参数不影响信任。
7. **跳转列表**：显示本地 Shell 任务，点击后打开对应终端；按 D1 开启后显示最近主机，点击后连接（锁定时先解锁）；删除主机后移除。
8. **任务栏进度**：传输时任务栏图标显示进度，扫描中为不确定状态，暂停为黄色、失败为红色，队列清空后消失。
9. **通知**：窗口不在前台时，大文件传输完成或失败、连接意外断开会弹 Toast，内容符合 D1；前台时不弹；关闭设置后不弹；用户主动断开不弹。
10. **Quake 模式**：设置热键后可在任意应用中呼出或隐藏；热键冲突时有明确提示；隐藏期间会话继续运行，呼出后回滚完整。
11. **Windows Hello**：启用后锁定 Vault 可用指纹或 PIN 解锁；取消 Hello 后可用主密码；停用后只能用主密码；复制到另一台电脑的便携数据回落到主密码，且不损坏 Vault。
12. **自动更新**：手动检查能发现新版本并按纯文本显示说明；确认后下载、验签、安装并重启到新版本；错签、篡改、降级或中断时保留现有版本并提示；安装失败后旧版本仍能启动。未配置公钥时显示不可用。
13. **可访问性**：Win11 高对比度主题下，新增界面以及解锁、主机列表、终端标签、SFTP 面板、传输队列、命令面板、设置的文字、焦点和状态都可辨认，状态不只靠颜色区分；新增功能都能只用键盘完成；reduced-motion 下没有过渡和窗口动画。
14. AGENTS.md 交付前检查全部通过；真实 OpenSSH、安装和更新脚本没有运行的，如实标为未运行或 skip。

1. 连接一台 Linux 和一台非 Linux 主机，对比状态栏；最小化 1 分钟后恢复，确认数值继续刷新。
