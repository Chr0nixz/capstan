## P2（已修复）：恢复旧备份没有清理不再匹配的 Hello enrollment

位置：`crates/capstan-core/src/lib.rs`，`VaultManager::restore_recovery_candidate`。

加固前，普通主密码解锁会调用 `cleanup_invalid_hello` 并设置失效提示；恢复流程在验证密码、替换主文件后直接发布已解锁 Vault，遗漏这两步。连续修改两次主密码后，sidecar 只保留最近两套 KEK；恢复更早的、仍合法的 Vault 备份时，sidecar 已无匹配的 KEK。随后密码修改进入 `stage_hello_password_change`，在认证旧 sidecar 时返回 `hello_data`。

这使已经通过主密码认证的恢复会话无法直接修改主密码，Hello 状态却仍为 enabled，且没有 invalidated 提示。主 Vault 没有被失败的修改破坏。该问题涉及 M4 §4.11 的失效清理和“主密码流程不变”，不依赖真实 Hello 硬件。

复现步骤：

1. 创建 Vault，以主密码 P0 启用 Hello。
2. 依次把主密码改为 P1、P2；保留自动产生的 P0 恢复备份。
3. 锁定，通过 `list_recovery_candidates(P0)` 和 `restore_recovery_candidate(token, P0)` 恢复 P0 备份。
4. 恢复成功后立即调用 `change_master_password(P3, revision)`。

仓库根目录运行本轮保留的独立探针：

```powershell
powershell -NoProfile -File target/m4-4-c-current-probe.ps1 -TestFilter recovery_should_clean_incompatible_hello_before_password_rotation
```

修复前实际结果：退出码 **101**，**0 passed / 1 failed**；完整九项探针为 **8 passed / 1 failed**。单项与全套各复现一次：

```text
after authenticated recovery: enabled=true, invalidated=false, rotate=Err("hello_data"), main_unchanged=true
authenticated password recovery must permit master-password rotation; got Err("hello_data")
```

修复前对照探针 `recovery_password_rotation_succeeds_after_disabling_invalid_hello` 通过：同样恢复 P0 备份后，先停用 Hello，再改为 P3，新主密码可以解锁。加固后不再需要这一步。

已实施修复：恢复候选完成密码认证与原子替换后，复用普通密码解锁的 `cleanup_hello_after_password_authentication`，再发布已解锁 Vault 和 `invalidated` 状态。临时不可用仍由既有清理逻辑保留 enrollment；清理发生 I/O 错误时保留恢复会话并提示需要清理。错误恢复密码不会触发清理。

新增的两项持久 Core 回归在修复前均失败，修复后均通过：

- `recovery_cleans_incompatible_hello_before_master_password_change` 覆盖 P0 → P1 → P2 → 恢复 P0 → 立即修改为 P3，验证错误恢复密码保留主文件及 sidecar、成功恢复后清理失效 sidecar 并提示、P3 可解锁且 P0 失效，以及后续无 enrollment 的恢复会清除旧提示。
- `recovery_remains_unlocked_and_reports_failed_hello_cleanup` 用含有文件的 sidecar 同名目录模拟不可清理状态，验证恢复仍成功、提示失效、保留未知文件且 Vault 仍可写。

探针源码和启动脚本为 `target/m4-4-c-current-probe.rs`、`target/m4-4-c-current-probe.ps1`；脚本按 Cargo JSON 输出选择依赖并编译，使用内存假 provider 和运行时随机密钥。它们是当前工作区的临时复现材料，清理 `target/` 后需重建；上述四步是独立于探针的复现流程。

## 已修复问题与其他边界

此前 P2 的定向回归：

```powershell
cargo test --locked -p capstan-vault store::tests::stale_vault_instance_cannot_disable_hello_after_password_change -- --exact --nocapture
```

实际 **1 passed**。停用前在文件锁内核对磁盘摘要；过期实例返回 Conflict，sidecar 保留。

修复前九项独立探针中，除上述恢复问题外，其余八项通过，覆盖：

- 另一实例修改密码、普通事务或替换 Vault 后，旧实例停用返回冲突，文件及密钥删除计数不变。
- 主文件缺失或损坏、实例已锁定时，停用不删除 sidecar；正常停用可重复执行。
- 双 KEK slot sidecar 逐字节翻转均拒绝解锁，还原后可解锁，主文件不变。
- 启用和解锁遇到取消或暂时不可用时保留原 enrollment，未发布的新密钥被清理。
- 错误主密码不能重新启用 Hello；损坏 sidecar 清理不授权原生密钥删除。
- 恢复旧备份后，先停用失效 Hello 可以恢复主密码修改。

现有 Vault 测试还覆盖单 slot 篡改、截断、超限、Vault 错配、错误 DEK/KEK、原子替换故障和密码轮换前后中断。Core 测试覆盖取消后主密码回退、成功主密码解锁后清理、锁定代次竞态；UI 测试覆盖五种 Hello 错误后继续使用主密码和重复提示拦截。

## 维护者手测清单

1. 启用 Hello 时重验主密码；取消后主密码和原 enrollment 仍可用。
2. 连续两次锁定并用 Hello 解锁，每次都出现新的 PIN/生物识别手势；取消后可改用主密码。
3. 修改主密码后，Hello 和新主密码可用，旧主密码失效。
4. 恢复两次密码变更前的备份，确认提示 Hello 已失效、可立即修改主密码并用新密码解锁；先用一次错误恢复密码，确认 sidecar 和主文件均保留。
5. 停用并重启后不再提供 Hello；换设备或 Windows 用户后，主密码解锁并清理失效 sidecar。
