# M4-1 交付记录

2026-11-03。Linux SSH 状态栏和共享契约已实现，待维护者在 Windows 桌面验收。

## 修改内容

- 新增 `M4-contract.json`，由 Rust 和 TypeScript 测试共同读取。快照采用 camelCase，字节、代次和 Unix 秒用十进制字符串，未采样时 `sampledAt` 为 `"0"`。同一 fixture 固定后续阶段的主题、启动请求、设置默认值和 Hello 错误码。
- 状态采集在首个 shell 就绪后启用，在已有 SSH 传输上执行固定 `sh` 命令。Linux 采集器每 3 秒读取 `/proc` 和 `df`。窗口最小化、切到本地标签或切到其他连接时停止发送采样请求，保留 exec 通道。首帧和恢复后的首帧建立差分基线，CPU 和网速从下一帧开始显示。
- 按维护者授权在 `capstan-ssh/src/pool.rs` 增加空闲通知。最后一个租约释放时关闭采集通道，并按原有 30 秒计时回收 SSH 传输。采集器按物理连接复用，界面按逻辑连接 ID 和代次接收快照。拒绝、解析失败和超限仅影响状态栏，同一 SSH 代次最多自动重开一次，可在详情手动重试。
- 2026-11-04 加固会话名额争用和 `df` 磁盘解析。shell 或 SFTP 因名额不足而等待状态采集让位时，清理任务先向状态通道发送 `TERM` 和 EOF，在有时限的等待中确认对端关闭，然后放行前台重试。`df` 只接受容量列与绝对挂载点能唯一切分的行。[加固和复测记录](M4-1-C.md)
- SSH 标签底部显示主机名、CPU、内存、根分区和网速。详情显示负载、挂载点和网卡，支持 Enter 展开和 Esc 收起。状态和错误说明提供中英文。

## 已知风险和未决问题

- `df` 超时或失败时采集暂不可用。实测非特权用户运行 BusyBox `df` 时，无权读取的 Docker 挂载点可导致该命令失败。单帧超过 64 KiB、网卡或挂载点超过 64 项、CPU 行超过 1024 项会显示采集超限。
- shell 和 SFTP 占满服务器的 `MaxSessions` 名额时，状态栏可能暂不可用。关闭额外会话后可从状态详情重试。远端若在有时限的让位清理后仍占用所有名额，前台重试可能被拒。缺少 POSIX `sh` 或 `uname` 的主机也可能显示采集不可用。
- Win11 原生窗口最小化与恢复、高对比度和实际非 Linux 主机仍待维护者手测。M4-3 的 Quake 隐藏与显示路径需同步调用 Rust 的 `status_commands::sync_visibility`，以覆盖 Tauri 未发送窗口事件的情况。

## 手测清单

1. 连接 Linux 主机，确认先出现内存和根分区，再出现 CPU 与网速。用 Enter 展开详情，检查挂载点和网卡，再按 Esc 收起。
2. 切换两个 SSH 标签和本地标签。最小化约一分钟后恢复，确认当前主机重新采样，本地标签没有状态栏。
3. 断网后恢复，确认新代次从新样本开始。若状态不可用，在详情重试并确认终端与 SFTP 仍可操作。
4. 连接非 Linux 主机，确认显示「仅支持 Linux」且 shell 正常。打开 Win11 高对比度主题，确认状态文字和键盘焦点清晰可辨。
5. 在 `MaxSessions 2` 的测试主机上等到状态栏出数，然后打开 SFTP，确认目录可浏览。关掉 SFTP，等采集恢复后打开同一连接的第二个 shell，确认两个 shell 都可交互。
