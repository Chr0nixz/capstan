# M3-3 断线处理与重连实施记录

2026-11-02 加固复审同步。[M3-3-C](M3-3-C.md) 最新复审确认 C1–C6 全部关闭，功能复审通过；维护者原生手测仍待验收。原先记录的 C6“待独立复审”已过期，本轮重跑连接恢复和 feed/controller 组合回归均通过。全仓格式检查仍有既有差异，不能记为全部交付检查通过。本次未修改产品实现、PLAN、C 报告、依赖、vendor、权限或发布配置，未初始化 Git、提交或推送。

## 修改内容

- SSH 启用 15 秒 keepalive、两次未响应后的超时检测；取消 60 秒无流量即关闭的设置。探测使用已有 transport 的全局 ping，不启动 shell。区分认证拒绝与认证中传输断开，后者可以退避重试；信任错误仍优先阻断。
- core 维护逻辑连接 ID、精确代次、状态、稳定错误码、窗格 owner 和受跟踪任务。连接状态事件与终端状态独立；新 transport 必须先发布更大代次的 connecting。
- 网络错误按 1、2、4、8、16、30、30、30 秒退避，八次失败后停止。网络或唤醒信号可提前触发探测和下一次重试。认证失败、指纹变化、锁库和取消停止重试；配置或凭据版本变化要求重新走受控主机启动流程。
- 新增 `connection_snapshots`、`reconnect_connection`、`disconnect_connection`；操作校验窗口来源和预期代次。`cancel_ssh_attempt` 等待启动或重连尝试回收；最后 pool waiter 的取消等待 factory 退出，旧 build 不能覆盖替代 build。
- Windows 主窗口注册唤醒消息 subclass 和接口变化通知，原生回调只投递有界合并信号。退出在窗口线程注销，再取消并等待事件任务和连接任务；注销失败时保守保留回调上下文，避免释放仍被借用的数据。
- UI 先订阅再查询状态，拒绝旧代次，允许通过权威快照补齐漏过的代次。断开时关闭并清空输入队列，保留 xterm 和回滚；重连创建独立 session、Channels、输出序列和输入队列，并插入中英文分隔提示。
- 旧 parser 输出在新 shell 接入前排空；迟到 ACK 仍归属旧 session。自动恢复不重放键盘输入、片段或主机 startup command。取消后显式点“重新连接”可保留屏幕并走新的主机启动流程，该显式流程沿用既有主机启动配置。
- SFTP 只自动重绑仍持有授权的中断下载：核对认证/信任策略、远端元数据、部分文件大小及已完成前缀。已有目标仍按 M2 再次请求覆盖确认。上传、本地授权已释放及进程重启后的任务继续要求原有选择/恢复流程。
- 锁库默认保留在线 transport，取消并等待凭据相关尝试；开启断开选项时继续执行原有全量清理。解锁本身不重新发送输入。跨解锁重新绑定到同一 pooled transport 的逻辑连接，显式断开时一起停止，避免其他 owner 自动重建。

实现位于 `capstan-ssh` 的 lib/pool/connection_state、core 的 lib/transfer/mod、Tauri 的 lib/connection_commands、UI 的 terminal/connections 及 i18n。更新共享 M3 状态 fixture 和相应测试，未修改其余历史报告。

## 根据 M3-3-C 加固

- **C1：恢复 Vault 后允许连接。** 恢复成功时清除 Core 的锁库标记，与普通解锁保持一致；新增进程内 SSH 回归，恢复含主机的备份后立即连接并进入 online。
- **C2：保留主动退出的 pane 终态。** 收到自然 `exited` 后不因共享连接的新代次 online 自动创建 shell；连接快照仍可见，用户显式重连时才通过主机启动流程创建新 shell。
- **C3：命令响应遵守状态迁移。** UI 控制器对重连命令响应使用与事件相同的状态迁移验证，忽略新代次已经 online 后迟到的 connecting 响应；新增事件/命令交错回归。
- **C4：取消等待限制到对应 attempt。** 取消仅等待仍属于该 attempt 的 monitor 收敛；代次或 attempt 转移会唤醒等待者，不再关闭并等待包含其他 owner 长期 monitor 的整条 TaskTracker。并发回归确认首个 owner 取消后其他 owner 可连接，取消调用不等待其 monitor 停止。
- **C5：更新 SFTP 中断说明。** 文档说明连接会自动退避重连、持有授权的当前进程下载在校验后自动重绑，以及上传、释放授权和进程重启任务仍需显式选择；保留已有目标再次覆盖确认要求。
- **C6：保留权威快照的补齐语义。** feed 为通过校验的快照附带内部来源 `event` / `query`，控制器仅允许权威查询补齐更大的连接代次；普通事件、命令响应和同代次状态仍遵守原迁移规则。来源不加入 IPC DTO，Rust/TS 共享 fixture 无需变更。

本轮仅修改 `ui/src/connections/{feed.ts,controller.ts}` 和对应测试，并新增 `recovery.test.ts`；文档更新限本报告和 board。新增 9 项真实 feed 与控制器的组合回归，覆盖漏失 connecting、跨多个代次及超过 JS 安全整数范围的代次、迟到命令/查询、parser 边界被更新代次赶超、释放后查询及输入零重放。修复前首批 7 项中 6 项失败，修复后组合回归 9/9、连接模块 31/31 通过。

## 已知风险和未决问题

- 未配置 `CAPSTAN_TEST_SSHD`，真实 OpenSSH 兼容测试明确跳过。Windows 实际睡眠、VPN/网卡切换和原生 WebView2 使用仍待维护者验收；原生自动化使用真实隐藏 HWND，但不代表真实设备唤醒已验收。
- 全仓 fmt 仍有 18 个文件、34 处既有差异；未扩大范围去格式化 benchmark、remote_edit、SFTP 或其他 transfer 文件。与加固前检查对照，没有新增差异。
- 自动恢复不能恢复远端进程，也不保证已提交输入的远端执行结果。重试耗尽后需要用户操作；主机或凭据配置变化时，可关闭旧窗格后重新打开主机。
- 上传需要重新选择源文件，覆盖目标需要再次确认，校验失败保留部分文件；这些沿用 M2 的数据安全边界。
- C1–C6 已由 2026-11-02 独立复审确认关闭，功能复审通过。阶段原生手测仍待维护者验收；组合测试使用真实 feed 和控制器、可控 IPC 与终端 transport，不代表已测得漏失事件时序在原生 WebView2 中的发生频率。
- 本轮未运行性能测量、打包发布、依赖审计和 vendor 专项；未改字节流合并、ACK 预算、SFTP 管线参数、测量代码或依赖，不作性能或发布结论。M3-4 隧道的自动重建由下一阶段接入本轮连接生命周期。

维护者手测清单：

1. 同主机开两个 SSH 窗格，退出其中一个，再让另一个断网恢复；退出窗格应保留结束画面，恢复窗格显示旧回滚、分隔提示和新 shell。
2. 断线时输入命令、粘贴或运行片段，恢复后确认没有自动发送；新输入只到新 session。
3. 睡眠/唤醒及反复切换网络，确认存活连接只探测，失效连接重连；连接恢复后窗格不应长期挂起，新输入可发送，其他窗格继续可用。
4. 重连中取消，等待网络恢复，确认不会自行重建；手动重新连接后检查回滚仍在。
5. 测试默认锁库与“锁库断开”，并在重连认证中锁库；解锁不应自动发送输入。
6. 中断下载后验证续传及再次覆盖确认；改变源文件后确认目标和部分文件均保留。上传确认仍需重新选择源文件。
7. 更换服务端主机指纹或制造认证失败，确认阻断且停止重试，并分别检查中英文提示。
8. 锁库后恢复含主机的备份，立即连接该主机。
