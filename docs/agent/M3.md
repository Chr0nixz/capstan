# M3 效率阶段

> 状态：可开始（M0–M2 已验收，见 [board](board.md)）。依据：[AGENTS.md](../../AGENTS.md)、[PLAN.md](../PLAN.md) §2.3–2.4、§4.6–4.10、§5–6、§8。
> 本计划细化既定 M3，不改变 PLAN 的范围或决定。需要改变时先与维护者确认，并在 PLAN 决策记录留痕。

## 1. 目标与范围

M3 让维护者能在同一个工作区并行处理多个终端任务，安全地广播输入、重连 SSH、恢复适用的 SFTP 任务、建立 SSH 隧道，并快速调用常用命令和操作。连接状态必须可信；重连不能假装恢复旧 shell，也不能重放不确定的输入。

本阶段包括：

- 标签内任意嵌套分屏、拖动调整窗格大小、标签拖动排序。
- 选择多个窗格广播终端输入；参与广播的窗格有红色边框；多行广播输入发送前二次确认。
- SSH keepalive 断线处理、自动重连、Windows 睡眠唤醒和网络变化后的连接恢复。
- 本地 `-L`、远程 `-R` 和动态 SOCKS5 `-D` 端口转发；支持手动启停和随 SSH 连接自动启动。
- 保存、分组、编辑和搜索命令片段；模板变量可设默认值，支持发送到当前窗格或广播，并可配置是否附加回车。
- `Ctrl+Shift+P` 命令面板，搜索连接主机、运行片段、切换主题和其他已注册操作。

不包括服务器状态栏、Windows Hello、任务栏、通知、Quake 模式、主题导入和自动更新（M4）；不扩展到 ARM64、macOS/Linux、跳板机或其他协议。M3 完成不等于授权发布、打 tag、提交或推送。

## 2. 实施阶段

阶段按依赖顺序推进。每阶段先实现契约和测试，再开始依赖它的阶段；阶段出口未通过时先收敛当前阶段。

| 阶段 | 工作 | 出口条件 |
| --- | --- | --- |
| M3-0 契约 | 固定 Pane、连接状态、隧道、片段和命令动作的 Rust/TS 边界；核对 russh 的转发能力及 Windows 唤醒/网络事件入口。 | DTO、状态迁移、取消所有权、错误码和测试范围有代码前审查记录。若发现 PLAN 未覆盖的产品决定，暂停该项并按仓库规则请维护者确认。 |
| M3-1 分屏与广播 | 前端建立窗格树；拆分创建独立终端会话；调整比例、重排标签、窗格选择和广播确认。 | 嵌套布局、输入路由、多行确认、关闭单窗格和隐藏 WebGL 生命周期均有测试。 |
| M3-2 片段与命令面板 | 片段加密保存、分组、模板填写、发送目标及自动回车；命令面板搜索并调用已注册动作。 | 变量/默认值/取消/目标/回车行为有测试；命令面板不引入任意命令执行入口。 |
| M3-3 断线处理与重连 | 建立连接级状态与代次；keepalive、网络变化和系统唤醒触发探测/重连；按 M2 策略恢复可恢复传输。 | 断线、重试、取消、锁库、主机指纹变化和旧 shell 终态均有自动化覆盖；无旧输入重放。 |
| M3-4 端口转发 | 在已有 SSH 连接上实现 `-L`、`-R`、SOCKS5 `-D`；加入 Vault 配置、状态/流量和自动启动；与 M3-3 生命周期衔接。 | 三种转发各有集成测试；占用、服务端拒绝、停止、重连和任务清理有覆盖；单隧道失败不关闭其他通道。 |
| M3-5 整体验收 | 跑完整工程检查、OpenSSH 兼容性测试和维护者手测；更新 board 当前状态及简短实施记录。 | 所有必需自动检查通过；手测清单通过或明确记录待维护者验收项；没有未处理的数据安全或连接生命周期问题。 |

## 3. 接口契约

具体 Rust 类型、Tauri 命令/事件名和 Rust/TS fixture 在 M3-0 固定。命名可以贴合当前代码，但不得改变以下边界和行为。

| 接口 | 契约 |
| --- | --- |
| 窗格布局 | UI 使用可序列化的二叉树：叶节点含稳定 `PaneId` 和 `TerminalLaunch`；分支含方向、0–1 比例和两个子节点。`TabId` 仍代表标签，`TerminalSessionId` 仍代表一个后端 shell；拆分 SSH 窗格通过正常启动流程创建同连接上的新 shell，不复制/伪造旧 shell 输出。窗格树和 xterm 实例不得混为一类状态。 |
| 输入广播 | 普通模式下，焦点窗格产生的输入只进入该窗格自己的有界终端输入队列。显式广播模式下，同一输入改路由到本地选中的目标窗格集合；集合为空时不发送并显示状态，不扩大目标范围。包含换行的广播粘贴在任何目标收到字节前确认；取消时所有目标均不收到内容。目标部分失败时报告失败目标，不自动重放已发送字节。 |
| SSH 连接状态 | 连接级快照至少包含 `ConnectionId`、连接代次、状态和稳定错误码；状态区分连接/认证、在线、重连中、已断开和失败。发布连接状态不替代每个 `TerminalSessionId` 的终端状态。旧代次的迟到事件不能改变新连接状态。 |
| 隧道配置 | Vault 保存带 `TunnelId`、`HostId`、自动启动标记的有标签联合类型：local `{bind_host, bind_port, destination_host, destination_port}`；remote `{remote_bind_host, remote_bind_port, local_destination_host, local_destination_port}`；SOCKS5 `{bind_host, bind_port}`。运行快照至少含状态、错误码、活动连接数和双向字节数。端口范围和地址在 Rust 校验。 |
| 隧道运行时 | 隧道持有自己的监听器、转发任务和 SSH 通道租约；启动/停止是幂等或返回稳定冲突错误。不得为 SSH 转发另建 SSH TCP 连接；新客户端流通过对应 SSH 连接上的转发通道处理。默认本地监听限于 loopback，向其他网卡监听必须显式配置。SOCKS5 本阶段仅要求 TCP CONNECT。 |
| 命令片段 | Vault 中保存片段 ID、分组、名称、模板和 `auto_enter`。模板支持 `{{变量}}`、`{{变量:默认值}}`；运行时收集的变量值不回写片段。目标为当前窗格或已选广播窗格。发送仍走终端输入，不运行隐藏 shell，不记录模板、变量值或终端内容。 |
| 命令面板 | 面板从显式注册的本地动作集合搜索和分发，动作使用稳定 ID 及 i18n 标签/关键词；主机连接和片段运行调用现有受控流程。不得把用户搜索文本当成命令、路径或任意进程参数。 |

## 4. 不变量

- 领域逻辑放在 Rust crate；`crates/*` 不依赖 Tauri，`src-tauri` 只做参数/权限检查、DTO、Channel 和原生系统事件接线。
- SSH shell、SFTP、隧道和状态任务复用兼容配置的同一 `ConnectionPool` 连接。连接复用键、安全隔离和最后通道关闭后 30 秒空闲保留规则沿用 PLAN §2.4。
- 每个窗格有独立 `TerminalSessionId` 和有界输入队列；终端输出继续经 Tauri Channel 原始二进制传输，并按现有 ACK/背压规则工作。不得改成 JSON 字节数组或 Base64。
- 仅可见窗格挂载 xterm WebGL renderer；窗格隐藏或卸载时释放 renderer。调整布局不得重启未变更窗格的 session。
- 连接断开后旧 shell 进入终态，已有回滚保留并插入重连分隔提示。重连建立新连接/代次和新 shell，不恢复远端进程，不重放输入。
- 只对网络/瞬时连接故障自动退避重试。锁库、用户取消、认证失败和主机指纹变化必须停止或等待用户操作；指纹变化始终阻断，不静默接受。
- SFTP 任务仅按 M2 已有恢复策略续传。重连后重新绑定时验证目标身份、大小和偏移/已完成前缀；不满足条件时要求选择、重试或清理，不猜测覆盖。
- 自动启动的隧道只在其所属连接已连接后启动；每条隧道的失败、取消和清理相互隔离。Vault 锁定或连接关闭时遵从现有断开策略并回收关联任务。
- 隧道和片段配置属于 Vault 加密数据；兼容旧 Vault，新增缺省字段有默认值并测试旧数据读取/备份导入。不得把配置明文复制到 settings.json。
- 前端不接触 SSH 凭据，不得开放通用 shell/fs 插件或任意本地路径。所有可见文本进入 `zh-CN` 和 `en` i18n；日志不得包含凭据、片段内容、变量值或终端字节。
- 用户输入只在用户确认后发送；不因广播失败、重连或片段重试而重复提交可能已到达远端的字节。

## 6. 测试命令

按阶段运行对应测试；分屏/终端布局变化必须跑 layout 检查，跨层状态/DTO 必须有 Rust 与 TS 覆盖。交付前运行完整清单：

```powershell
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo clippy --workspace --all-targets --features tauri-runtime -- -D warnings
cargo test --workspace
cargo test -p capstan-app --features tauri-runtime
pnpm -C ui typecheck
pnpm -C ui test
pnpm -C ui test:layout
pnpm -C ui test:sftp-layout
```

受影响范围的针对性命令：

```powershell
cargo test -p capstan-ssh
cargo test -p capstan-terminal
cargo test -p capstan-core
cargo test -p capstan-vault
cargo test -p capstan-app
```

SSH/SFTP/隧道集成测试使用进程内 russh 服务端，不依赖 Docker。配置 `CAPSTAN_TEST_SSHD` 时运行真实 OpenSSH 兼容测试；未配置时必须保留明确 skip：

```powershell
$env:CAPSTAN_TEST_SSHD = "user@127.0.0.1:2222"
cargo test --workspace
Remove-Item Env:CAPSTAN_TEST_SSHD
```

若新增或升级依赖，另跑：

```powershell
cargo deny check all
powershell -NoProfile -File scripts/Check-Licenses.ps1
```

测试要覆盖输入无丢失/乱序、广播取消和部分失败无重放、连接代次隔离、网络中断和唤醒、主机指纹变化阻断、SFTP 续传校验、三种转发、端口占用/拒绝/取消、隧道任务回收、旧 Vault 兼容及片段变量处理。性能不作门槛；只有改到终端或传输核心路径且维护者提出，或日常使用出现退化时才按 AGENTS.md 测量。

## 7. 验收标准

自动化和手测均需覆盖以下结果：

- 可在一个标签中创建多层水平/垂直分屏并拖动调整比例；标签可重排。关闭一个窗格不关闭其他窗格或同连接任务，切换标签不会丢失各自屏幕和 session。
- 广播只发给选中窗格，目标有红色边框；多行粘贴在确认前不发送，取消后零目标收到；失败时准确显示目标，不重复发送。
- 断网时连接状态及时转为重连；网络恢复或 Windows 唤醒后按退避重连。旧 shell 清晰结束并保留回滚，分隔提示出现，新 shell 使用新 session；输入不重放。
- 自动启动配置的隧道在连接恢复后重建，手动隧道不擅自启动；断开、取消或锁库后关联监听器、任务和通道均回收。
- 本地、远程和 SOCKS5 转发分别通过自动化集成测试；端口占用和服务器拒绝有清楚错误；停止一个隧道不影响 shell、SFTP 或其他隧道。
- 可恢复 SFTP 任务经身份/偏移校验后依 M2 策略续传；不适用或校验失败时不覆盖目标、不丢弃部分文件且不谎报完成。
- 片段支持分组、搜索、变量/默认值、当前窗格/广播和可选回车；保存后仍在加密 Vault 中。命令面板可用 `Ctrl+Shift+P` 搜索并运行计划范围内的动作。
- 中英双语、键盘操作和错误状态可用；只有可见窗格使用 WebGL。旧 Vault 可读写，新字段不泄露到明文设置或日志。
- AGENTS.md 交付前检查全部通过；真实 OpenSSH 未配置时明确标为未运行/skip，不能写成通过。

维护者手测清单（十项以内）：

1. 在本地终端和 SSH 标签分别创建嵌套分屏、拖动尺寸，再重排标签。
2. 在两个 SSH 窗格间切换焦点，确认单窗格输入不会误发到其他窗格。
3. 勾选两个广播目标，确认红色边框；广播普通输入，再取消一次多行确认并检查没有窗格收到内容。
4. 创建分组片段，测试变量默认值、取消填写、发送目标和自动回车；重启后确认片段仍在。
5. 用 `Ctrl+Shift+P` 搜索并运行连接主机、片段、主题切换及其他已注册操作。
6. 分别验证本地、远程和 SOCKS5 转发；再验证端口占用和无权限远程转发的错误提示。
7. 关闭单个隧道和单个 pane，确认同连接中的其他 shell、SFTP 和隧道继续工作。
8. 在有可恢复 SFTP 任务时断网并恢复，核对目标文件和恢复结果。
9. 断网后恢复网络，以及 Windows 睡眠/唤醒后检查状态、旧 shell 提示、新 shell 和自动启动隧道。
10. 锁定 Vault 或触发主机指纹变化，确认会话按策略停止且指纹变化被阻断。
