## 审查意见处理

- **C1：聚焦窗格协议回复误入广播。** 新增 `panes/xtermInput.ts`，在 xterm 5.4 的同步输入分发处保留 `wasUserInput` 标记。`session.ts` 据此区分用户输入与协议回复；来源不按焦点或字节字符串猜测。缺失、只读或无法识别的来源接口会停止托管窗格输入并显示失败，不猜测投递目标。
- 协议回复经 `sendProtocolInput` 直接进入来源会话已有的有界目的 FIFO，不读取广播选择，也不等待用户多行确认；它仍排在该 FIFO 已接受的数据之后。用户输入继续使用原源队列、目标快照和确认流程，用户主动输入与协议回复相同的字节仍可广播。
- **投递边界澄清。** 取消、来源关闭和切换标签的零投递承诺限于目标 FIFO 接受用户数据之前。已被目标 FIFO 接受的数据继续处理；来源随后关闭不撤回或重发这些数据。新增测试固定两侧语义。
- 本轮修改仅涉及终端输入入口、M3-1 来源适配/路由及对应测试、B 报告和 board；C 报告保留独立审查原貌。未新增依赖或修改 Rust、PLAN、vendor、权限/CSP、发布流程及 M2 历史材料。

## 修改内容

- `workspace.ts` 接入 M3-0 的二叉 Pane 树，保存稳定 PaneId、方向、比例、焦点及各窗格的会话状态。向右/向下拆分可以继续嵌套；新窗格通过现有启动流程创建独立 shell。SSH 每次使用新的 attempt ID，连接复用仍由原连接池负责。
- 新增 `panes/tree.ts`、`PaneWorkspace.tsx`：使用固定版本 `react-resizable-panels@3.0.6`（MIT）调整尺寸，支持拖动和分隔条方向键。终端使用稳定 DOM 容器和独立 portal；拆分、合并、调整比例及切换标签保留已有 xterm、回滚和 controller。
- 标签支持本窗口内拖动排序，以及标签按钮上的 `Alt+Shift+左/右`。终端面板始终按创建顺序挂载，避免 React StrictMode 因标签换位重跑会话副作用；有专门回归测试。
- 关闭窗格只清理自身启动尝试、controller、renderer 和输入端点；关闭最后一个窗格沿用关闭标签的流程。原标签关闭按钮及 `Ctrl+Shift+W` 仍关闭整个标签。SFTP 跟随标签内焦点窗格，绑定对应 TerminalSessionId。
- 新增 `panes/input.ts`、`inputQueue.ts`：普通用户输入进入自身窗格，广播只发送到当前标签明确勾选的集合；空集合阻断用户输入并显示状态。源队列在入队时固定路由和端点 owner，改变焦点、选择或广播模式不会扩大已排队输入的范围。每个目的窗格有独立的 64 KiB / 256 项有界 FIFO，普通输入、广播输入和自身协议回复共用该目的队列。
- 广播目标显示完整红框和勾选状态。用户输入中的任何 CR/LF（包括单独 Enter、末尾回车及 bracketed paste）均按 M3-0 契约确认；弹窗列出目标，默认焦点为取消。投递前固定目标 ID、输入及端点 owner；目标 FIFO 接受前取消、关闭来源或切换标签时零用户输入投递，旧输入不能进入重启后的新 shell。
- 部分失败逐目标返回稳定错误码，未知 IPC 结果标为 `delivery_unknown`，不重放成功或失败目标。实际写入失败的目的窗格结束输入并显示手动重启入口；其他窗格继续工作。队列满等失败与结果不确定均有清楚提示，关闭目标后仍保留其原窗格编号供报告使用。
- 新增或扩展 workspace、PaneWorkspace、输入路由、TerminalPane 和 App 测试；新增中英文字及快捷键说明。未修改 Rust、共享 DTO fixture、vendor、权限/CSP 或 M2 历史材料；终端二进制输出、解析后 ACK 和背压路径沿用原实现。

## 已知风险与未决问题

- Chrome fixture 使用隔离浏览器且关闭 GPU；不代表原生 WebView2、真实 ConPTY/WSL/SSH、IME 或显卡上的手测通过。renderer 挂载/释放由现有 session 测试及新增多窗格组件测试验证，实机仍待维护者确认。
- xterm 5.4 的公开 `onData` 不提供来源；适配器使用当前固定依赖的内部 `coreService.triggerDataEvent`。升级 xterm 时须保留真实 xterm 与 Channel 注入回归，并核对这一接口；不支持的来源接口停止托管窗格输入。
- 成功结果只表示输入命令已被接受，不保证远端命令执行完成。失败或未知结果不重发；使用者应检查目标，再显式决定后续输入或重启。
- 窗格布局和广播选择保留在当前窗口内，本阶段未加入重启后恢复。密集嵌套分屏仍受窗口可用尺寸限制。
- C1 已完成修复及实现方验证，独立复审仍待进行；下列手测及 M3 后续阶段仍未验收。

## 维护者手测清单

1. 本地 PowerShell、WSL 和 SSH 分别向右/向下嵌套拆分；确认每个窗格是独立 shell。
2. 用鼠标及聚焦分隔条后的方向键调整比例，检查 vim/htop、中文和末行显示。
3. 切换焦点后输入，确认普通输入仅进入该窗格；检查 SFTP 跟随相应 SSH 窗格。
4. 拖动标签排序，再用 `Alt+Shift+左/右` 排序；切回后核对输出、回滚和远端进程仍在。
5. 开启广播但不选目标，确认输入阻断；勾选两个目标，确认只有它们显示完整红框并接收普通输入。
6. 取消一次多行粘贴及一次 Enter 的广播确认，核对所有目标均未收到字节；再确认发送一次。
7. 在选中的一个目标退出或断开后广播，检查失败目标提示、其他目标没有重复输入，以及手动重启入口。
8. 关闭中间窗格、最后一个窗格及整个标签，确认其他标签、同连接的 shell/SFTP/传输继续工作。
9. 反复切换、隐藏和关闭多个分屏标签，检查 WebGL/显卡资源、焦点、中文 IME 和高 DPI；分别检查中文/英文、深色/浅色。
10. 聚焦窗格在广播两目标、空目标、来源未选中及多行确认等待期间触发终端状态查询，确认回复只回到来源，其他 shell 不收到协议回复。
