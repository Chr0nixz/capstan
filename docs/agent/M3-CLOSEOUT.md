## 本次复核修复

- **片段广播漏确认。** `auto_enter=false` 且不含换行的片段绕过确认，违背 PLAN 的“片段每次确认”决定。`ui/src/App.tsx` 现在对所有非空目标的片段广播强制确认。`App.test.tsx` 覆盖开关自动回车、已确认的目标集、取消零投递、再次运行重新确认，以及确认后的部分失败无重放。新增反例修复前实际投递一次，修复后 App 46 项通过。
- **隧道错误状态的清除时机。** 之前成功客户端必须结束才清除错误，旧流结束或不完整 SOCKS 请求又会误清目标连接错误。`crates/capstan-ssh/src/forwarding/runtime.rs` 现在在目标连接成功时立即清除错误，普通客户端结束只处理容量提示。`crates/capstan-core/tests/forwarding.rs` 新增两项回归，修复前均失败，修复后隧道集成测试 23/23 通过；原有 64 客户端上限、停止、拒绝、重连和通道隔离测试继续通过。

## 已完成的前置修复

- **隧道客户端异常隔离。** 客户端自行断开、SOCKS 握手不完整或既有流重置，不再被记为隧道级错误；单个客户端在 accept 前重置不会让监听器整体失败。本次进一步修正错误的清除时机。
- **Vault 降级兼容。** M2 构建的 `VaultData` 拒绝未知字段，而 M3 构建写入的载荷总会带上三个空列表，所以只要 M3 构建写过一次，M2 构建就打不开这个 Vault。现在空列表不写入，没有片段和隧道的 Vault 仍可被 M2 构建打开。改动在 `crates/capstan-vault/src/model.rs`，并新增单元测试。[VAULT-FORMAT.md](../VAULT-FORMAT.md) 补充说明：保存过片段或隧道后，旧构建无法再打开这个 Vault。
- **片段模板的字面花括号**（维护者 2026-11-03 决定，已记入 PLAN 决策记录）。原实现会拒绝保存含非变量 `{{…}}` 的模板，例如 `docker ps --format '{{.Names}}'`。现在只有 `{{名称}}` 和 `{{名称:默认值}}` 是变量，其他内容按原样发送；编辑器提示同步更新。注意 `{{end}}` 这类单个标识符仍算变量。改动在 `ui/src/snippets/`，补了模板和编辑器测试。

## 后续调整

维护者 2026-11-03 确认，已记入 PLAN 决策记录：

- **重试用尽后自动恢复。** 原来 8 次网络重试失败后连接停在失败状态，之后网络恢复或唤醒都不再重连，断网超过约两分钟时每个窗格都要手动重启。现在网络变化或唤醒信号会为 `reconnect_exhausted` 的连接重新开始一轮退避；认证失败、指纹变化、锁库和取消仍然停止。新增测试 `a_network_signal_restarts_an_exhausted_retry_cycle_without_replaying_input`，关掉恢复逻辑时失败；认证失败用例补充了“收到信号也不重试”的检查。
- **合并导入不再重复。** 片段分组按名称合并；完全相同的片段，以及同一主机上相同的转发会跳过。原来同一份备份导入两次，隧道会重复，两个自动隧道会争同一个端口。
- **手动停止的自动隧道保持停止**，直到再次手动启动或应用重启；原来重连后它会自己恢复。编辑、锁库断开和覆盖导入造成的内部停止不受影响。
- **客户端上限提示。** 隧道已有 64 个活动客户端时，新客户端仍会被关闭，但会显示 `client_limit` 提示；之后有客户端正常结束，提示就会消失。新错误码已加入共享 fixture，Rust 和 TS 同时校验。

## 契约核对

| 边界 | 结论 |
| --- | --- |
| 窗格与广播 | 二叉窗格树，稳定的 `PaneId`；每个目标一个有界 FIFO，确认完成后才投递。确认规则按 2026-11-02 决策：琥珀色标记，同一目标集第一次发送换行时确认，多行和片段每次确认。协议回复只回来源窗格；部分失败只报告，不重放。 |
| 连接状态 | 代次单调递增，旧代次快照被拒绝。只有超时和连接错误按 1–30 秒退避，最多重试 8 次；锁库、取消、认证失败和指纹变化都会停止重试。 |
| 重连 | 旧 shell 进入终态，新代次打开新 shell，不重放输入和 startup command；自动隧道重建，手动隧道保持停止。 |
| 隧道 | 复用同一 transport 上的通道，不另建 SSH 连接；UI 默认监听 `127.0.0.1`。远端撤销未确认前，保留失败状态和连接租约。 |
| 片段与命令面板 | 配置保存在加密 Vault 中；变量值不回写片段；命令面板只分发已注册的动作。 |
| 安全边界 | 新命令只接受 `main` 窗口；没有新增插件、权限或 CSP 改动；新代码不输出日志。 |

## 维护者手测

手测前：M2 审查包是便携版，使用自己的 `data` 目录。如果让 M3 构建打开 M2 构建也在用的 Vault，先导出一份 `.cbak`；M3 构建保存过片段或隧道后，M2 构建就打不开这个 Vault 了。

以下十项均待维护者确认，合并原 M3-5 和后续调整的清单：

1. 本地 PowerShell、WSL、SSH 创建嵌套分屏并调整比例、重排标签；核对旧输出、进程、IME、高 DPI 和隐藏/显示后的绘制。
2. 普通输入只进入焦点窗格，SFTP 跟随焦点；广播只进入选中目标，首次换行和多行按规则确认，协议回复仅回来源。
3. 广播单行片段，分别开关自动回车：每次都确认，取消零发送；目标部分失败显示原因，成功目标不重复执行。
4. 保存含中文变量、默认值及 `docker ps --format '{{.Names}}'` 的片段；取消填写零发送，重启后配置保留，同一备份合并两次不重复片段或隧道。
5. `Ctrl+Shift+P` 搜索并运行主机、片段、主题和注册动作；核对中文输入法 Enter、Esc、快捷键以及中英文提示。
6. 验证本地、远程和 SOCKS5 转发及域名解析；端口占用/服务端拒绝有明确提示，停止一个隧道不影响其他 shell、SFTP 或隧道，远端撤销失败可重试停止。
7. 目标连接失败后结束旧客户端或中止 SOCKS 握手，错误仍保留；目标恢复后保持新客户端连接，错误立即清除；正常浏览后关闭页面不产生伪错误。
8. 断网超过三分钟再恢复，以及 Windows 睡眠/唤醒和网卡切换：新 shell 有分隔提示和旧回滚，没有输入或 startup command 重放，主动退出的窗格保持结束。
9. 手动停止自动隧道后断网恢复，它保持停止而其他自动隧道重建；手动启动后下一次重连可恢复。重连中取消及两种锁库策略均正确回收或保留任务，认证失败/指纹变化始终阻断自动重试。
10. 中断可恢复下载后重连，核对身份、大小、前缀校验和再次覆盖确认；改变源文件后目标与部分文件保留，上传仍要求重新选择源文件。
