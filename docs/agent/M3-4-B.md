# M3-4 端口转发实施记录

2026-11-02 完成 `-L`、`-R` 和 SOCKS5 `-D` 的实现与自动化覆盖；根据 [M3-4-C.md](M3-4-C.md) 加固 C1–C4 后，针对性回归及本轮 workspace 测试通过。没有新增依赖，没有修改 `docs/PLAN.md`。

## 修改内容

- SSH 层在现有认证连接上复用转发通道，实现本地、远程和 SOCKS5 TCP CONNECT。运行时跟踪任务、连接数和双向字节数；单隧道故障不会关闭其他隧道或 shell。每隧道最多接纳 64 个活动客户端。
- Core/Vault 将隧道配置保存在加密数据中，校验主机引用、端口和地址；旧数据缺失字段默认为空，schema 0 迁移初始化空隧道列表。备份导入会重映射隧道与主机 ID。
- 启动校验所属主机、连接 ID 和代次，只允许已在线的兼容连接启动。自动隧道随首次连接及重连启动，手动隧道不会自动重启；编辑、删除、主机删除、连接断开和应用退出会停止并回收关联任务。锁库沿用 `disconnect_on_lock`：启用时随 SSH 会话清理隧道，关闭时保留在线连接及其隧道。
- 主机删除现在也移除对应的已停止运行时绑定和重连抑制标记，避免状态查询继续返回已删除隧道的快照；新增集成回归验证配置/快照清除和监听端口回收。
- Tauri 增加隧道配置、启停及状态事件命令，并限制到 `main` 窗口。连接和隧道事件任务在 Tauri Tokio runtime 中安装，避免同步 setup 调用 `TaskTracker::spawn` 时缺少 reactor。UI 提供中英文配置、状态、错误、连接数和精确流量显示；默认监听 `127.0.0.1`，删除前确认。连接身份来自已成功启动的 SSH shell。
- 新增进程内 russh 集成测试，覆盖三种转发、半关闭和流量计数、端口占用、服务端拒绝、通道拒绝、停止与端口回收、重连自动启动、手动隧道不自动启动、Vault 加密、旧数据读取及备份合并。
- 按维护者授权，在 `crates/capstan-vault/src/envelope.rs` 为 schema 0 迁移补空隧道列表初始化；在 `ui/src/App.tsx` 和 `ui/src/terminal/TerminalPane.tsx` 完成面板挂载及连接身份接线。

## C1–C4 加固

- 远端撤销请求被拒绝或超时后保留 `Failed / remote_forward_rejected` 和待确认的端点注册、连接租约；停止重试继续处理未决请求，收到确认或 SSH 传输关闭后才释放。编辑、删除主机/隧道及覆盖导入在监听器未确认回收时失败并保留 Vault 配置；UI 显示原因并提供“重试停止”。
- 首次连接取得租约后，在启动自动隧道和首个 shell 前安装连接监督。首次 PTY/shell 被拒绝或取消时，连接尝试 owner 释放，仍被自动隧道持有的连接继续受监督并可重连。
- 隧道启停使用按 ID 独立的操作锁；启动确认在配置和绑定锁释放后等待，慢速远程启动不再阻塞兄弟隧道停止。启动中可停止；UI 忽略较晚到达的旧启动响应。
- `crates/capstan-core/tests/forwarding/hardening.rs` 覆盖远端撤销拒绝、超时后的迟到确认、覆盖导入保护、首个 PTY 拒绝/取消、慢启动期间停止兄弟隧道、停止启动中的远程隧道，以及自动启动慢响应隔离。
- 主机删除按稳定顺序先处理远程隧道，再处理本地和 SOCKS5 隧道；远程撤销失败会在任何本地 sibling 停止前返回，Vault 配置、本地 sibling 和尚未处理的远程 sibling 保持不变。新增四条同主机隧道的确定性回归测试。

## 已知风险与未决项

- 真实 OpenSSH 上的远程转发权限、`GatewayPorts` 行为和跨网络访问尚未手测；远程绑定范围由 SSH 服务端策略决定。
- 服务端持续拒绝或不确认远端撤销时，隧道会保持失败并占用待清理状态；这是为了避免谎报监听器已释放。用户需重试停止，或等待 SSH 传输关闭；受影响的配置编辑、删除和覆盖导入会暂时失败并保留原数据。
- 主机删除遇到远端撤销拒绝时会保留同主机隧道配置、本地 sibling 及尚未处理的远程 sibling；失败撤销的远端转发仍需按 C1 的重试停止流程回收。
- SOCKS5 只支持无需认证的 TCP CONNECT。每隧道并发客户端上限为 64；达到上限时新客户端会被关闭。
- 维护者尚未完成日常使用验收。建议手测：
  1. 分别配置本地、远程和 SOCKS5 转发，确认目标可达；SOCKS5 使用域名目标验证由 SSH 服务器解析。
  2. 验证本地端口占用和服务端拒绝远程转发时显示对应错误，shell、SFTP 和其他隧道继续可用。
  3. 模拟远端撤销拒绝和超时，确认失败状态保留；恢复服务端确认后重试停止，并确认端口释放。撤销未确认时尝试编辑、删除和覆盖导入，确认 Vault 配置未丢失。
  4. 服务端拒绝或取消首次 PTY 请求，同时保留自动隧道；随后断开 SSH，确认连接监督触发重连且不恢复旧 shell 或重放输入。
  5. 延迟远程隧道启动响应，同时停止兄弟本地隧道及启动中的隧道，确认停止不等待无关启动响应。
  6. 有活动客户端时停止一个隧道，确认连接结束、监听端口释放、流量计数正确，其他隧道保持运行。
  7. 配置三种自动隧道及一个手动隧道，断线重连后确认自动隧道恢复而手动隧道保持停止。
  8. 编辑、删除隧道或所属主机并退出应用，确认关联任务和通道回收；分别在 `disconnect_on_lock` 开启与关闭时锁库，核对隧道按策略停止或保留。
  9. 将含隧道的 Vault 备份合并到另一 Vault，确认主机与隧道 ID 重映射；打开旧 Vault 后确认兼容。
