## 1. 阶段目标与交付结果

> 前一有界预检源码检查点：独立目标快照及目录树同层检查每批至多 3 项，祖先先查，错误时等待已开始的原生快照完成；不改变全局提交锁、完整哈希、认证和预算。新增 4 项回归及新一轮 18 项必需检查、15 项工具检查通过（Rust 329/14/351、UI 195），审查包为 `m2-review-873a32487d0e`，0.1.0。实际 SFTP/core、高 RTT 目录树哈希及清理通过；上传单轮约 131.7 秒，耗时比降至 1.950，仍超 1.5；下载比 1.400，未形成正式三轮中位数。当前源码正式 localhost 目录树及 3 × 1 GiB 文件各 16 个完整样本通过；目录树总耗时比为 0.405/0.328，文件吞吐比 1.538/1.564、总耗时比 0.583/0.632，绝对门通过。最新范围与待办以 [M2-B](M2-B.md) 和[当前证据](baselines/M2/raw/2026-10-21-preflight/README.md) 为准，前台继续延后，M2 仍 `blocked`。

M2 的目标是让维护者在同一个 SSH 工作区完成浏览远程目录、传输文件、修改权限和编辑配置文件，减少在终端与独立 SFTP 工具间切换。文件工作流必须复用已建立且已验证身份的 SSH 连接，并且不能拖慢终端、绕过主机信任或在失败时破坏原文件。

### 1.1 必须实现的用户结果

1. SSH 连接成功后自动打开 SFTP 面板；切换标签时展示对应会话的目录，本地 PowerShell/WSL 标签不显示 SFTP。面板可停靠右侧或下方、调整尺寸和折叠。
2. 可以手动输入路径、返回父目录、刷新、显示隐藏文件、复制路径，完成文件/目录新建、重命名、删除确认和权限修改。
3. 可以通过选择器和拖拽上传、下载文件与文件夹；默认全局并发 3 个传输任务，显示进度、速度、剩余时间以及可操作的失败原因。
4. 可以暂停、取消、重试；可 seek 的常规文件在校验目标和已完成范围后续传。固定条件下至少 1 GB 文件的中断续传必须完成且两端 SHA-256 一致。
5. 同名目标明确选择覆盖、改名或跳过；排队期间和提交前发生的目标变化也必须重新处理，不能沿用过期确认直接覆盖。
6. 双击支持的文本文件后，由配置的本地编辑器打开受控临时副本；保存后自动回传。检测到远端并发修改时保留远端版本和本地修改，交由用户决定。
7. 安装 shell 集成后，SFTP 可跟随当前标签的工作目录；不安装仍可完整使用手动浏览和传输。集成安装、重复安装和卸载不损坏用户已有配置。
8. 传输过程中仍可输入终端命令、切换标签、打开第二个 shell；关闭一个标签不会误关其他 shell 或后台传输使用的连接。
9. 提供可复现的 SFTP/OpenSSH 兼容报告、与 WinSCP 的同条件性能比较、M1 回归结果、维护者手测清单及 v0.2 候选包。

### 1.2 完成的含义

浏览列表成功、传完一个小文件或测试服务端通过，只证明对应子任务。M2 完成需要 A/B 两道门通过，真实 OpenSSH、Windows 拖拽/编辑器和固定性能验收有记录，冲突与失败路径保留用户数据，且没有未关闭的必需项。

## 3. 范围与顺序

| 领域 | A 门：安全文件闭环 | B 门：完整 SFTP 工作流 |
| --- | --- | --- |
| 协议与连接 | `russh-sftp` 可行性、基准、共享浏览 SFTP、生命周期、协议限制 | 同连接最多 3 个 SFTP 的受控租约、多 shell/多任务共享、错误隔离、真实兼容矩阵 |
| 浏览与操作 | 跟随活动标签的面板、手动路径、目录分页、基础操作及确认 | 大目录交互、右/下停靠、完整键盘操作及双语错误状态 |
| 传输 | 单文件上传/下载、临时目标、覆盖保护、取消回收 | 文件夹、双向拖拽、3 并发、流水线、进度/速度/ETA、中断续传 |
| 编辑 | 文件类型、临时目录、编辑器调用及能力契约冻结 | 下载/编辑/监测/回传、并发冲突、关闭与残留清理 |
| 目录跟随 | OSC 7 输入验证契约与测试夹具 | xterm 接线、每标签跟随开关、shell 集成安装/卸载 |
| 验收 | 进程内服务端与真实 OpenSSH 最小闭环 | 1 GB 续传、WinSCP 对比、M1 回归、维护者验收与候选包 |

明确不纳入本阶段：自动断线重连和睡眠恢复、旧 shell 恢复、分屏/广播、隧道、命令片段、命令面板、服务器状态、Windows 任务栏进度/系统通知及自动更新。它们继续按 M3/M4 推进。

M2 的断线处理是准确终态与显式重试：用户重新连接后，可将经验证的传输任务绑定到新连接续传；不自动重放终端输入。跨进程持久化传输队列、目录同步、远端到远端复制、内置编辑器和文件系统挂载不作为本阶段交付承诺。异常退出残留的发现与安全清理仍是必需项。

| `crates/capstan-ssh/src/sftp/`（新增模块） | SFTP 握手、协议能力、句柄、请求分发、流水线和通道故障；封装所选库，避免上层绑定第三方内部类型 |
| `crates/capstan-core/src/sftp/`（新增模块） | 会话绑定、路径授权、文件操作、浏览状态与稳定领域错误 |
| `capstan-core` 的 `transfer`、`remote_edit`、`shell_integration` 模块 | 队列/续传、冲突策略、编辑生命周期、集成文件事务与清理；与 Tauri 无关，可独立测试 |
| 既有原生 Windows 适配边界 | 文件/目录选择、OS 拖入/拖出、编辑器选择和启动；平台接口向 core 提供受限能力 |
| `src-tauri` | 来源与参数校验、命令 DTO、进度订阅、原生能力接线及退出协调 |
| `ui/src/sftp/`、`ui/src/transfers/`（新增） | 面板、文件列表、传输队列、冲突和编辑会话交互；通过 controller/transport 与 Rust 通信 |
| `ui/src/terminal/session.ts` | 只转交 xterm 已解析的 OSC 7 和会话身份，不拥有 SFTP 连接或文件操作 |

`crates/*` 不依赖 Tauri；Vault 不依赖 SFTP，终端核心不承担文件传输。先在现有 crate 内按职责拆模块，不为未来功能建立通用插件框架或新增无明确边界的 crate。`App.tsx` 负责组合入口，新增业务不继续集中到单个大组件。

### 4.2 连接、租约和取消

- 一次真实 `ConnectionId` 最多有 3 个活动 SFTP subsystem（2026-10-20 维护者批准的变更）。多个浏览标签共享主 subsystem，传输任务取得全局 worker 后独占分配一个数据 subsystem；总数包含主 subsystem。每个槽位并发打开合并握手，初始化失败或取消必须清理后才可重建。208 在途请求、128 等待者和 64 远程句柄在整条连接上共享，每个 subsystem 另遵守服务端句柄限制；不能按子系统放大额度。
- SFTP 由既有已认证连接开通道。不得通过启动隐藏 shell、解析 `sftp` 命令行输出或另建 TCP 连接完成正常文件操作。
- core 保存 `TerminalSessionId → ConnectionId / connection generation / host binding` 的关系，并验证调用窗口；前端的标签、主机 ID 和字符串不是连接授权。
- 浏览视图各自保存路径、筛选、选中项和跟随开关；同一连接的两个 shell 可以位于不同目录。所有操作携带绝对远程路径或受控 entry ID，不使用共享的可变“服务器当前目录”。
- 浏览订阅、传输与编辑会话按需要持有租约；缓存不能永久持有强引用形成环。关闭所有用户后释放 SFTP 句柄/任务，再进入既有 30 秒连接空闲回收。
- 不在等待文件 I/O 或队列消费时长时间持有整个 SSH connection mutex。SFTP 背压只能限制自身任务，必须给同连接 shell 保留处理机会。
- 取消从窗口/工作流传到请求，带超时并等待任务回收。服务端可能已完成的写入返回不确定结果，重新查询验证，不能因本地超时直接判定“未执行”并重放删除/覆盖。

| 事件 | 必须发生的行为 |
| --- | --- |
| 切换/折叠面板 | 停止不必要的浏览请求或更新订阅；传输继续，折叠不等于取消 |
| 关闭一个 shell 标签 | 释放该浏览绑定，保留仍有任务的传输/编辑租约；用户仍能从队列访问任务 |
| shell 自然退出 | 终端标记结束并保留回滚；不由已退出 shell 永久占用租约，不把 SFTP 仍在线误报为 shell 在线 |
| SFTP subsystem 拒绝或单通道失败 | 面板显示具体错误，其他 shell 继续；不得把它误报为 SSH 认证失败 |
| SSH 传输断开 | 结束该代次的请求，任务进入 `interrupted`；重连后旧句柄/事件失效，续传必须重新验证 |
| 默认 Vault 锁定 | 已授权的活动连接及任务按既有策略继续；不读取新的凭据，不创建新认证连接；已解锁远端内容仍可见的边界写入说明 |
| 选择锁定时断开全部连接 | 取消 SFTP/编辑回传和传输、关闭连接并回收；本地未上传修改进入可恢复状态，不能直接删除 |
| 退出应用 | 展示未完成传输/编辑的处理选择，完成取消、保存副本或明确放弃后清理；拒绝退出时保留工作状态 |

### 4.3 标识、命令与事件

标识分离：`SftpSessionId` 是后端工作流能力，`BrowseRequestId`/目录修订区分迟到结果，`RemoteEntryId` 引用原始文件名，`TransferId` 与 `EditSessionId` 拥有任务生命周期，`LocalSelectionToken`/`ExportToken` 表示用户选定的本地来源或目的地。它们不能互相替代，均需校验所有者、代次、有效期和操作范围。

命令组至少包含以下能力；名称是冻结接口的起点，不表示已存在：

| 命令组 | 输入与输出边界 |
| --- | --- |
| `attach_sftp` / `detach_sftp` | 已运行的 SSH 终端会话 → 绑定的 SFTP 会话、能力和状态；不接受密码/私钥或任意连接配置 |
| `list_remote_directory` / `stat_remote_entry` | 会话、路径/entry ID、请求代次和分页 cursor → 有界元数据；取消旧请求 |
| `create_remote_entry` / `rename_remote_entry` / `delete_remote_entries` / `set_remote_permissions` | 会话、受验证目标、预期属性及必要确认 token → 单项/批次结果 |
| `select_transfer_source` / `select_transfer_destination` | 调用原生选择器或消费真实 OS drop → 受限 token 和显示名称 |
| `enqueue_transfer` / `pause_transfer` / `resume_transfer` / `cancel_transfer` | 会话、来源/目标 token、冲突策略 → 任务 ID；重试保持任务身份并增加代次 |
| `begin_remote_edit` / `resolve_edit_conflict` / `close_remote_edit` | entry ID、编辑器配置 ID、明确决策 → 编辑会话与状态；没有通用“执行命令”参数 |
| `update_remote_cwd` / `preview_shell_integration` / `apply_shell_integration` | 绑定的终端及 OSC 数据，或用户选定文件与预览 token → 校验结果/事务结果 |

状态/进度使用有界、合并的元数据订阅；初始快照与后续事件有单调版本，可重新获取快照。终态不能被进度覆盖或丢弃。取消、断开、切换标签后拒绝旧代次事件。字节数和 SFTP 64 位整数采用不丢精度的 Rust/TS 编码，不能直接假定所有 `u64` 都是安全 JS number。

文件正文直接在 Rust 本地 I/O 与 SFTP 间传输，不通过 JSON、base64、React 或 Zustand。保留现有终端二进制 Channel 协议；文件进度不能占用它的 ACK 或字节预算。新增 Rust/TS 契约 fixture，覆盖字段命名、可选值、整数和稳定错误码。

稳定错误至少区分：`sftp_unavailable`、`permission_denied`、`path_invalid`、`unsupported_file_type`、`target_conflict`、`resume_mismatch`、`local_io`、`remote_io`、`editor_unavailable`、`connection_lost`、`operation_canceled`。UI 使用 zh-CN/en 文案和可行动的上下文，不直接展示第三方错误或把所有错误归为连接失败。

### 4.4 路径、文件名和本地能力

- 远程路径按远端协议处理，不能使用 Windows `PathBuf` 自动替换分隔符。URI 仅在 OSC 入口解码一次；手动输入不是 URI，不做隐式二次解码或 shell 展开。
- 目录条目的文件名、大小、属性和类型都来自不可信服务器。限制包长、条目数、单名长度、目录深度和在途目录句柄；列表分批读取/渲染，不一次构造无界数组。
- 对目录条目的 `.`、`..`、分隔符、NUL 和异常编码做显式处理。非 UTF-8 文件名不能经有损转换后用于写操作：优先由 opaque entry ID 保留原始字节；若所选库无法无损支持，清楚标记不支持，拒绝相关操作并记录兼容限制。
- 浏览时可明确进入符号链接指向的目录；递归复制/删除不自动跟随 symlink，删除链接只删除链接本身。循环、悬空链接和类型改变均有测试。远程权限以服务端最终响应为准。
- 原生选择器/OS drop 取得本地能力后，Rust 只允许访问选择的文件或目录范围；过期、跨窗口或伪造 token 失效。前端不能提交任意本地路径换取通用读写能力。
- 下载落盘校验目录穿越、绝对路径、UNC/设备路径、NTFS ADS、Windows 保留名、尾部点/空格、大小写及规范化碰撞。不可表达的名字需要改名/跳过决策，不能静默合并或覆盖。
- 本地递归操作检查 symlink、junction/reparse point 和目录逃逸；校验必须延续到实际打开/创建时，不能仅对最初字符串做一次前缀比较。默认不穿越链接，越界项单独报告。
- 日志和通用诊断只记录 ID、计数、状态和错误类别；不记录文件正文、终端内容或凭据，也不默认持久化完整主机/路径清单。编辑器设置、面板位置等非秘密偏好可进入 `settings.json`；敏感目标信息不得借传输队列明文长期存储。

### 4.5 文件操作、提交与冲突

新建文件使用排他创建语义；重命名与删除确认包含主机、路径、类型和范围。递归删除显示目录范围，检查条目类型并支持取消；批次部分成功逐项呈现，不宣称可整体回滚。chmod 显示原值/目标值，不隐式递归修改，失败不伪造成功状态。

上传和编辑回传写入远程同目录随机临时文件，下载写入目标目录的受控临时文件；成功写完、关闭并完成必要验证后才提交正式目标。刷新列表只在提交后反映最终文件。取消/失败不截断已有目标；不得为实现覆盖先删除正式文件。

在协商确认支持时使用原子替换扩展，并记录 rename、覆盖和持久化能力的区别；普通 rename 成功不等于所有服务器都支持原子覆盖，也不等于已经持久化到磁盘。服务器不支持安全替换时，提供另存为或明确说明风险的替代路径，不能静默降级成先删后写。rename 请求结果不确定时先核验正式文件与临时文件。

冲突判断绑定目标属性快照，至少包含大小、mtime 和类型；在用户决策后、提交前复查。目标出现、消失、改名或属性变化都重新进入冲突处理。“覆盖全部/跳过全部”只能作用于明确选择的当前批次；编辑冲突不继承传输队列的全局覆盖选项。

属性比较存在 TOCTOU 及相同大小/mtime 下漏检的可能；不能宣称无损消除所有并发修改。保留原文件、临时副本和明确失败结果，并在帮助/报告中说明边界。

### 4.6 传输调度、续传与资源上限

默认全局 3 个活动传输 worker，文件夹任务按需枚举并将子文件交给同一个预算；不得“3 个目录 × 每目录无限并发”。每文件使用有界多请求流水线，调度公平覆盖同连接的多个任务，目录浏览/取消不能被大文件长期饿死。

M2-01 冻结并测试：请求大小、每文件在途请求数、全局缓冲字节、等待任务数、递归深度、目录页大小、操作超时、取消期限和事件频率。建议首个探针从每请求 32 KiB、每文件 16 个在途请求开始，再按协议能力与测量调整；这些是探针起点，尚不是性能结果。内存随并发预算受限，不随文件大小线性增长。

状态至少覆盖 `queued → preparing → running → verifying → committing → completed`，以及 `paused`、`interrupted`、`awaiting_conflict`、`failed`、`canceled`。暂停停止新请求并收敛在途请求；取消终止当前任务并处理受控临时文件。进度按已确认的有效字节计算，速度不包含等待用户决策的时间；枚举未结束或样本不足时 ETA 显示未知，不能伪造稳定剩余时间。

续传必须执行以下步骤：

1. 原任务保存目标身份、主机指纹/身份策略、源文件基线、受控临时文件标识与已确认范围。失联时冻结状态；禁止仅用“相同路径字符串”识别原任务。
2. 用户显式重连/重试后重新取得合法会话。验证目标、用户名、信任和认证策略；不同 `ConnectionId` 可以是同目标的新代次，不同身份/指纹不能自动继承续传。
3. 对源文件、临时文件和最终目标重新 `stat`/检查类型；仅常规可 seek 文件可续传。大小缩小、目标变化、临时文件身份无法确认或偏移越界均阻断，提供重新传输/改名/跳过。
4. 校验已完成前缀：除大小和 mtime 外，比对源与部分目标的前缀哈希或等效分块校验。上传通过 SFTP 读回验证，下载检查本地 partial 与远端；不要求远端安装 `sha256sum` 或允许任意 exec。
5. 流水线乱序确认可能留下空洞；可续传位置是已验证的连续前缀，不能直接取文件长度、已发送字节数或最大 ACK offset。未知尾部经验证后覆盖/截断，最终长度必须准确。
6. 完成剩余写入后重新校验源/目标状态并提交。无法证明可继续时从头传输，不能为成功率跳过验证。测试夹具使用双方完整 SHA-256 验证结果；只有实际做过完整校验才能向用户声称“哈希校验通过”。

同一正式目标的多个本应用写任务串行处理；跨应用/远端修改仍按冲突规则。源文件持续变化不保证获得一致快照，应阻断或要求稳定副本。初始传输、续传验证和提交阶段分别计时，不能通过漏计验证开销美化性能。

拖入与拖出都必须覆盖文件和目录。上传只消费真实 Windows drop 事件授予的来源；下载拖到 Explorer 需验证原生导出数据对象、准备阶段、用户取消及临时 staging 清理。M2-01 做最小可行性探针；只有下载按钮不能签收“拖拽下载”。

### 4.7 远程编辑生命周期

- 首版以常规文本文件为对象，冻结字节上限和文本判定规则，拒绝目录、设备、FIFO 和不支持类型。传输保留原始编码/换行字节，不擅自转码。通过编辑器修改可执行配置时不能执行该远端文件。
- 使用应用专属随机子目录、受限访问权限和不冲突文件名；原生选择并保存编辑器可执行文件，参数按独立 argv 传递，不拼 shell 命令，文件路径不解释为选项/脚本。启动失败保留可恢复状态。
- Rust 管理编辑会话、文件监测和回传队列。覆盖编辑器原地写、临时文件+rename、连续快速保存；等待文件稳定后串行上传最新版本，不在文件尚未写完时回传。
- 打开时捕获远端基线，回传前复查；成功后更新基线。远端变化、断线或上传失败保留本地修改，状态明确可见；不能只显示一个短暂通知后删除副本。
- 冲突提供查看/保留双方、另存为、显式覆盖或放弃本地修改；默认不覆盖。覆盖确认绑定当时远端版本，提交前再次变化则重新处理。不得用旧基线连续覆盖后来修改。
- 编辑器可复用已有进程；不能将启动进程退出等同于编辑完成。提供显式结束编辑入口；关闭 shell 不静默结束编辑会话。
- 正常结束/退出先完成回传、保存到用户选择位置或明确放弃，再删除工作临时文件。启动时识别本应用拥有且不被其他实例使用的残留；含未上传/冲突数据先提供恢复导出或确认放弃，避免清理掉唯一副本。
- 清理只作用于可验证所有权的随机目录及任务文件，拒绝路径逃逸和链接替换；不扫描删除系统临时目录中的其他文件。远程临时文件也只清理本任务可确认拥有的文件，断线后的未清理结果可追踪。

### 4.8 OSC 7 与 shell 集成

数据路径固定为 `SSH bytes → xterm parser → OSC 7 callback → bounded cwd event → Rust validation → SFTP navigation`。parser 回调快速返回，网络操作异步执行，不阻塞终端解析/ACK。事件包含源终端、连接代次和序号，并合并频繁更新。

- 只接受约定的 `file://host/absolute/path` 形式，限制长度；拒绝非 file scheme、userinfo、非预期 port、query/fragment、非法百分号、NUL、控制字符及越界路径。
- authority 必须匹配当前连接的规范化目标或用户明确绑定到该会话的主机别名。短名/FQDN/IPv6 与配置地址不同需明确处理；不能仅凭终端输出或 DNS 相似性扩大接受范围，也不将空主机/localhost 自动视为任意远端。
- Rust 再校验主机绑定和路径范围，结合 SFTP `realpath`/服务端可访问命名空间处理；不能借本机路径规则把远端 `/` 或合法父目录导航误判为越界。拒绝格式/作用域逃逸后保留原目录。
- 每个终端有独立 cwd；隐藏标签的事件只更新其状态，不能移动活动标签的面板。手动导航关闭该标签的自动跟随，重新开启才使用最近有效 cwd；读取失败保留当前列表并显示原因。
- OSC 7 是不可信的目录提示，不证明远端进程实际 cwd，不授予本地文件访问、写远端文件或执行命令的能力。

首个 shell 集成支持矩阵以 Linux Bash/Zsh 为目标，分别验证交互/login 场景和现有 prompt hook 共存；其他 shell 未验证时保留手动路径，不宣传通用支持。安装入口让用户选择具体启动文件并预览差异；自动打开 SFTP 不自动安装集成。

安装器通过文件事务插入带版本与唯一标记的最小区块，正确编码 hostname/path 的 OSC 7 URI，不拼接未转义路径到命令。先检查文件类型、权限、大小、编码和现有标记，备份原始字节；对 symlink/异常标记/安装后用户改动明确拒绝或进入人工处理。写入失败保留原文件；重复安装不追加区块，卸载只移除能准确识别的未改动区块，保留其余字节与权限。无关内容在安装前后发生修改时必须重新预览，不能用旧备份覆盖整个文件。

### 4.9 界面与交互约束

沿用现有 graphite/light、紧凑行布局和活动主机上下文。文件列表使用名称、大小、类型/权限、修改时间等稳定列；列表和队列保留行身份，进度更新不重排正在操作的项目。大目录使用分页/虚拟化，面板 resize 后正确 fit 终端，不重复创建 xterm 或挂载隐藏 WebGL renderer。

加载、空目录、无权限、SFTP 不可用、已断开、等待冲突、失败和取消分别显示。删除确认可取消；错误后的重试目标可辨认。键盘可到达列表、路径栏、队列与对话框，关闭对话框恢复焦点；所有新文字和原生提示提供 zh-CN/en。保持最小窗口、缩放、高对比和 reduced-motion 下可用，不用颜色独自表达风险。

### 7.2 性能方法与通过规则

1. **预登记与冻结。** M2-00 在首次测量前写入 `docs/agent/baselines/M2/performance-policy.json`；M2-01 用固定参考测量生成绝对阈值并保留 policy/原始数据哈希。以下是待验证的工程目标，不是已测结果：大文件双向有效吞吐分别不低于同条件 WinSCP 三轮中位数的 **80%**；小文件树端到端耗时不高于 WinSCP 的 **1.5 倍**。若无法达到，记录原因、优化或提出具体方案，不能测完后自行放宽。
2. **环境一致。** 固定机器/电源模式、Windows/WebView2、release 构建、视口、服务端/OpenSSH、认证、实际协商算法、压缩、存储与路径。固定 WinSCP 版本和 SFTP 设置；单任务对单任务、3 并发对 3 并发。记录实际 RTT 的测量方法，不能把 TCP connect 时间写成 RTT；至少覆盖本地低延迟和可控的较高 RTT 场景，注明注入点/带宽/抖动。
3. **负载。** 大文件采用精确 **1 GiB（1,073,741,824 字节）**，满足 PLAN 的至少 1 GB 要求；另有固定 manifest 的多层小文件树、空文件/空目录/隐藏文件/中文与空格名。数据由种子生成不可压缩内容，不提交大文件。上传、下载、单任务、3 并发均测；每场景预热后至少 3 轮，报告全部样本和中位数。
4. **中断验证。** 双向分别在早期/中段/接近完成时强制断开，记录实际确认偏移及重连身份；校验续传确实复用了已验证数据，最终大小和两端 SHA-256 全等。加入源/partial/目标被改动负例，必须拒绝续传或重新确认；不能仅截断进度显示模拟断网。
5. **计时公平。** 分别记录排队、枚举/准备、有效数据传输、续传验证、提交与完整性验证耗时，报告端到端总时长。用于比较的步骤、验证成本与 WinSCP 配置对齐；无法对齐的附加成本单列，不能只挑传输最快区间宣称达标。
6. **终端回归。** 复跑 M1 原场景及冻结阈值；另跑同连接多个 shell 与 3 个传输、一个慢请求/慢 ACK 的组合。无丢字节/乱序，输入 p95 与新负载的明确预算均须通过；新负载预算也必须在候选测量前冻结。保留本地和 SSH 各 100 MiB、三轮 20 标签生命周期及可见/隐藏 renderer 检查。
7. **资源。** 记录应用+WebView2+拥有子进程的峰值工作集/CPU/句柄、应用数据缓冲峰值、请求/文件句柄/任务数、退出/空闲后的回收；外部编辑器独立标注。缓冲不得超过契约预算，文件大小翻倍不能导致缓冲线性翻倍；关闭后会话/任务/订阅归零，连接按既有策略回收。
8. **结果解释。** WSL loopback 只证明该环境，不扩大到所有 WAN/存储；合成输入响应不等于实际键盘/GPU 延迟。所有失败轮次保留，工具版本与参数可复现。报告用数值及冻结门槛作结论，不写无阈值的“接近 WinSCP”。

沿用 M1 参考的适用条件；设备/系统变化确需新参考时，另存环境与阈值形成过程，不能覆盖旧报告或把不同环境数据直接混算。性能探针和故障注入仅用于显式启用的测量构建，生产候选拒绝测试入口。

### 9.2 优先风险及处理

| 风险 | 最早验证点 | 处理原则 |
| --- | --- | --- |
| `russh-sftp` 与现有补丁/协议能力不兼容或吞吐不足 | M2-01 | 先测并冻结结果，定位请求/窗口/调度；确需替换方案时提交证据和影响，不能以增加第二条 SSH 连接绕过 |
| 单连接 SFTP 占满窗口使 shell 延迟回归 | M2-02、06 | 限制在途字节/请求、避免跨通道锁与读任务阻塞；保留真实同连接压力回归 |
| 拖出到 Explorer 需要原生能力且取消/暂存困难 | M2-01 | 尽早验证文件与文件夹，形成平台适配和清理契约；未实现不得以选择器下载冒充 |
| 目标变化、弱 rename 语义、续传 ACK 不确定 | M2-03、07 | 受控临时目标、连续前缀校验、能力检测和显式冲突；保留原文件和可恢复副本 |
| shell 集成破坏用户启动配置 | M2-10 | 明确选文件、预览、备份、幂等标记、原始字节/权限保留和失败注入；无法确认时停止写入 |
| 编辑器保存与清理并发造成数据丢失 | M2-08、11 | Rust 状态机、保存稳定检测、串行提交、拥有权校验；未回传数据先导出/明确放弃再清理 |
| 测试环境/实机证据不足 | M2-12、13 | 保留 `needs-maintainer-manual` 或具体 `blocked`；明确缺项，不把 skip、模拟或编译通过当作真实验收 |

### 9.3 M2 完成与 M3 入口

只有 A1–A6、B1–B8 的必需项通过，重大正确性/数据安全问题修复，性能阈值与维护者受影响范围验收有证据，才将 M2 总体记为 `accepted`，给出“可发布 v0.2 候选并进入 M3”的结论。发布/tag/提交/推送仍由维护者另行指示。

留给 M3 的应是可复用的连接/通道租约、准确的传输中断状态、经验证的续传入口和明确会话代次。自动重连后，M3 可以调用这些入口重新建立 SFTP 工作流；它不能把旧 shell 进程或未确认操作重放包装成恢复成功。
