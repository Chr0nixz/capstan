## 修改与审查意见处理

| 意见 | 本轮处理 |
| --- | --- |
| C1 广播确认遗漏 CR | 使用 `/[\r\n]/`；覆盖 CR、LF、CRLF、结尾回车和 bracketed paste。取消返回空投递集合；真实投递前零发送由 M3-1 接线测试验证。 |
| C2 同代次重连回到在线 | Rust/TS 均拒绝 `reconnecting → online/authenticating` 同代次迁移。实际重连必须以更大代次的 `connecting` 开始，再进入认证/在线；旧代次迟到快照不能覆盖新状态。 |
| C3 判别字段强制转换 | 连接状态、隧道状态和面板字段先检查原始字符串类型；数组、对象、null 和数字均拒绝。 |
| C4 片段长度跨层不同 | 统一按 UTF-8 字节计数：分组名 128、片段名 256、模板 8192；共享用例覆盖中文、emoji 的恰好上限及越界。TS 同时拒绝 Rust JSON 无法解码的孤立代理项，并对齐 Rust 的空白字符规则。 |
| C5 校验边界不同 | 活动连接数限于 `u32`；地址按现有 `normalize_target` 接受 DNS、IPv4、IPv6/作用域，拒绝非法分隔符等输入；连接 ID 拒绝全零 UUID。补齐片段/隧道配置的非零 ID 校验。 |
| C6 出口记录不足 | 下文固定命令/事件名、DTO、取消所有权、锁库及部分失败行为，核对当前 russh 和 Windows API。Rust 新增两个事件常量，与 TS/fixture 共同校验。 |

保留原有 Pane 二叉树、显式命令动作及三类转发 DTO。共享 `M3-contract.json` 由 Rust/TS 共同读取状态、整数、地址和 Unicode 边界反例；Pane/动作属于 UI 本地契约。未增加依赖，未修改 PLAN、vendor、权限、CSP 或 M2 历史材料。

## 接口与生命周期审查记录

本轮在后续运行时实现前补齐以下约定，不追认此前已有完整代码前审查。新命令暂未注册；接线时需增加相应参数、返回值和来源校验测试。

所有新增命令仅接受 `main` 窗口调用。下表为 Tauri 的 camelCase 参数名；内部 DTO 字段维持共享 fixture 的大小写。`ExactU64` 为规范十进制字符串，范围 `0..=18446744073709551615`；代次从 1 开始。新增持久化命令的 `expectedRevision` 和返回 `revision` 同样使用该字符串，不改变已有命令签名。失败返回现有 `{code}`，不夹带服务器文本、片段或输入内容。

| 阶段与命令 | 参数 → 成功返回 |
| --- | --- |
| M3-1 复用 `start_local_terminal` / `start_ssh_terminal` | 沿用现有 options 或 hostId/attemptId、输出与状态 Channel → 新 `TerminalSessionId`；SSH 返回所属 connectionId。拆分每次创建独立 shell。 |
| M3-1 复用 `write_terminal_input` / `stop_terminal` | `{id,input}` / `{id}` → `void`；输入仍入各 session 有界队列，输出与 ACK 协议不变。 |
| M3-2 `list_snippets` / `list_snippet_groups` | `{}` → `Snippet[]` / `SnippetGroup[]`。 |
| M3-2 `save_snippet` / `save_snippet_group` | `{snippet,expectedRevision}` / `{group,expectedRevision}` → `{revision:ExactU64}`。 |
| M3-2 `delete_snippet` / `delete_snippet_group` | `{id,expectedRevision}` → `{revision:ExactU64}`；被片段引用的分组返回 `group_in_use`。 |
| M3-3 `connection_snapshots` | `{}` → `ConnectionSnapshot[]`，先订阅事件再查询快照，按代次校验更新。 |
| M3-3 `reconnect_connection` | `{connectionId,expectedGeneration,attemptId}` → 新代次 `connecting` 快照；只登记一次尝试，后续状态经事件发布。 |
| M3-3 `disconnect_connection` | `{connectionId,expectedGeneration}` → 回收完成后的 `disconnected` 快照。旧代次操作返回 `invalid_input`，不操作新连接。 |
| M3-3 强化 `cancel_ssh_attempt` | `{attemptId}` → `void`；接线时补齐返回前等待该尝试回收，不取消同连接的其他持有者。 |
| M3-4 `list_tunnels` / `tunnel_runtime_snapshots` | `{}` → `TunnelConfig[]` / `TunnelRuntimeSnapshot[]`。 |
| M3-4 `save_tunnel` / `delete_tunnel` | `{config,expectedRevision}` / `{id,expectedRevision}` → `{revision:ExactU64}`；修改运行配置前先停止并等待该隧道回收。 |
| M3-4 `start_tunnel` / `stop_tunnel` | `{id,connectionId,expectedGeneration}` / `{id}` → `TunnelRuntimeSnapshot`；重复启动同一运行实例返回现状，重复停止返回 stopped。停止返回前已完成回收；错误代次/配置返回 `invalid_config`。 |

`connection-state-changed` 载荷为 `ConnectionSnapshot`，`tunnel-state-changed` 载荷为 `TunnelRuntimeSnapshot`。连接 ID 是受控流程中的逻辑连接标识，实际 transport 每次替换增加 generation；现有 `SshConnection::connection_generation()` 与新快照的映射由 M3-3 接线。隧道 owner 按连接代次隔离、串行发布状态，旧实例回收后不得再发布事件。

连接/隧道错误码以 Rust 枚举及 TS 常量为准；存储沿用 `vault_locked`、`vault_conflict`、`not_found`、`invalid_input`、`vault_io` 等现有稳定码。自动重试只处理网络/瞬时连接错误；用户取消、认证失败、锁库和指纹变化停止或等待操作。`reconnecting` 表示原 transport 已失效；系统事件触发探测但原连接仍在线时保持 online。

广播为 UI 本地操作，不新增任意命令执行入口。先固定并去重目标集合，确认后每个目标仅尝试一次；取消或空集合不调用输入命令。结果固定为 `{deliveredPaneIds:PaneId[],failedTargets:{paneId:PaneId,errorCode:string}[]}`：delivered 仅表示队列已接受，不保证远端执行；失败返回该目标的稳定终端错误码，IPC 结果不确定映射 `delivery_unknown`。不自动重发任何目标；再次发送必须由用户显式操作。M3-1 测试须覆盖确认前零调用、取消零调用、部分失败及结果不确定时无重放。

片段执行在 UI 收集变量，取消填写时零发送，变量值不回写；自动回车在路由确认前附加，再按完整输入判断多行风险。命令面板只分发显式 `CommandAction`，搜索文本不进入后端执行参数。

### russh 转发能力核对

已检查当前 `vendor/russh/src/client/mod.rs` 的实际签名，无需修改 russh。

| 类型 | API 与接线范围 |
| --- | --- |
| 本地 `-L` | 本地 listener 接受 TCP 后，通过已有 handle 的 `channel_open_direct_tcpip` 打开目标通道；转为流做双向拷贝并正确处理 EOF。 |
| 远程 `-R` | `tcpip_forward` 请求服务端监听；实现 `Handler::server_channel_open_forwarded_tcpip`，按本连接代次及已注册监听地址/端口找到隧道，再连接配置的本地目标。未登记的回调通道立即关闭。 |
| 停止 `-R` | `cancel_tcpip_forward` 取消监听，关闭本隧道活动流并等待回收；服务端拒绝返回 `remote_forward_rejected`，不关闭其他通道。 |
| SOCKS5 `-D` | 本地解析 TCP CONNECT 后，对每条流使用同一个 handle 的 `channel_open_direct_tcpip`；不支持的命令明确拒绝。 |

配置端口固定为 `1..=65535`，不使用 russh 的服务端动态分配端口 0。默认本地 bind 为 `127.0.0.1`；其他网卡须显式配置。SSH TCP 仍由 ConnectionPool 统一持有，不为转发另建 SSH 连接。

### Windows 事件入口核对

当前 Tauri `on_window_event` 没有唤醒/网络事件接线，不能用窗口焦点代替。已核对本地 Win32 绑定：`WM_POWERBROADCAST`、`PBT_APMRESUMEAUTOMATIC`/`PBT_APMRESUMESUSPEND`，以及 `iphlpapi.dll` 的 `NotifyIpInterfaceChange`/`CancelMibChangeNotify2`。

M3-3 在允许的 `src-tauri` 新连接模块使用主窗口 HWND 注册消息 subclass，并注册 `AF_UNSPEC` 接口变化通知；该层只发送合并后的 probe 信号到 Rust 核心 supervisor。原生回调不解密凭据、不执行异步连接、不阻塞。优先用模块内最小 Win32 FFI，避免修改 vendor 或新增依赖。主线程移除 subclass；在通知回调之外取消网络注册，等回调退出后再释放上下文。M3-3 需补原生注册/注销、事件合并和取消竞态测试，睡眠/网络实机结果仍由维护者验收。

### 取消所有权与任务回收

| owner | 取消范围与完成条件 |
| --- | --- |
| Pane/controller | 拥有一个 session 和一次启动 attempt；隐藏/卸载立即释放 renderer。关闭 pane 取消未完成启动并等待 `stop_terminal` 回收该 session；其他 pane、SFTP 和隧道不受影响。 |
| 连接 supervisor（core），transport（ssh） | 每逻辑连接持有代次、重试 token 和受跟踪任务；显式断开先禁止新任务，再取消重试/启动、关闭子通道并 join，最后释放 transport。单个 pool waiter 取消不影响其他 waiter；最后通道退出仍沿用 30 秒空闲保留。 |
| Tunnel runtime（ssh），配置管理（core） | 每 TunnelId/连接代次拥有 listener、转发任务、通道租约和子 token；停止先停止接收/撤销远程监听，再取消流、关闭通道、等待全部 join 后发 stopped。单隧道失败只清理自身。 |
| SFTP/transfer service | 继续使用 M2 任务 owner；旧 shell 进入终态。新连接重绑须核对身份、文件大小、偏移/前缀，不能推断覆盖或重放不确定写入。 |
| 窗口/应用 | 持有原生注册和 supervisor；退出先注销系统回调，再取消并等待所有关联任务。回调上下文不得先于注销释放。 |

锁库沿用 PLAN §4.3 和现有 `lock_vault_and_cleanup`：默认取消凭据相关在途尝试/重试，禁止新的凭据读取，保留已在线 transport 及其既有通道；已有隧道可继续服务，不因网络信号新建 SSH transport。启用 `disconnect_on_lock` 时，取消关联重连、SFTP/传输和隧道，等待 listener、流、任务和 transport 回收。解锁不重放输入；自动隧道只随其所属新连接在线后重建，手动隧道保持停止。

## 已知风险与未决问题

- 本阶段只有 DTO、路由和验证逻辑；取消零投递、部分失败、重连、原生事件、SFTP 重绑及隧道回收尚需上述阶段的运行时集成测试。
- `VaultData` 尚无片段/隧道字段。旧载荷测试只证明现有 schema 1 可读；新增缺省字段、加密保存、备份合并/导入由 M3-2/M3-4 实现并测试，不能算作本阶段通过项。
- M3-4 需用进程内 russh 服务端覆盖三类转发、占用/拒绝/取消、重连与隔离清理；真实 OpenSSH 由环境变量启用。
- 尚待独立复审及维护者日常验收；本轮不更新 board 里程碑状态，不提交或发布。
