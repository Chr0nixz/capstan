## P2 · SGR 鼠标报告进入分屏广播

xterm 对旧式鼠标协议发出二进制事件，M4-2 已将它送到原窗格。SGR 协议的同一个右键事件则由 xterm 标为用户输入，经 `sendInput` 进入 `captureInput`。当前窗格开启广播时，报告会发给选中的目标窗格。报告中没有回车或换行，也就不会触发广播确认。这条 SGR 路径在 M4-2 前已存在，本次新增的原窗格路由只覆盖旧式协议。

实测使用真实 xterm 解析鼠标模式并生成右键按下报告，终端会话的两个发送回调分别记录出口。旧式协议通过，调用原窗格出口，字节为 `[27,91,77,34,33,33]`。SGR 失败，实际调用用户输入出口，字节为 `[27,91,60,50,59,49,59,49,77]`（`ESC[<2;1;1M`）。广播分发是根据源码确认的，探针测到会话出口为止。

[会话分流](../../ui/src/terminal/session.ts#L284) · [窗格输入路由](../../ui/src/terminal/TerminalPane.tsx#L256) · [广播确认](../../ui/src/panes/contracts.ts#L31)

将以下探针临时保存为 `ui/src/panes/m4-2-review.test.ts`，运行 `pnpm -C ui test src/panes/m4-2-review.test.ts`。预期两个用例都走 `source`。实测 1 通过、1 失败，退出码 1。

```ts
import { Terminal } from "@xterm/xterm";
import { expect, it } from "vitest";
import { createTerminalSession, type TerminalLike } from "../terminal/session";

it.each(["DEFAULT", "SGR"])("routes %s right click", async (encoding) => {
  const terminal = new Terminal({ allowProposedApi: true });
  const mouse = (terminal as unknown as { _core: { coreMouseService: {
    triggerMouseEvent(event: { col: number; row: number; button: number; action: number }): boolean
  } } })._core.coreMouseService;
  const observed: string[] = [];
  const session = createTerminalSession(document.createElement("div"), true, {
    terminal: Object.assign(terminal, { open: () => undefined }) as unknown as TerminalLike,
    rendererFactory: () => ({ dispose() {} }),
    fitAddonFactory: () => ({ fit() {} }),
    sendInput: (bytes) => { observed.push("user:" + JSON.stringify([...bytes])); },
    sendProtocolInput: (bytes) => { observed.push("source:" + JSON.stringify([...bytes])); },
  });
  try {
    const mode = "\x1b[?1000h" + (encoding === "SGR" ? "\x1b[?1006h" : "");
    await new Promise<void>((resolve) => terminal.write(mode, resolve));
    expect(mouse.triggerMouseEvent({ col: 0, row: 0, button: 2, action: 1 })).toBe(true);
    expect(observed).toEqual([encoding === "SGR"
      ? "source:[27,91,60,50,59,49,59,49,77]" : "source:[27,91,77,34,33,33]"]);
  } finally {
    session.dispose();
  }
});
```

## P3 · 目录批次重试把空等时间算进通知阈值

同一目录批次的两个 1 字节任务在 1 秒内分别完成和失败。60 秒时重试失败项，61 秒时完成。按 B 记录的计时口径，这次重试耗时 1 秒，且低于 100 MiB，预期无通知。实测首次结束时无通知，重试结束时返回一条 `TransferCompleted`。桌面层在窗口持续后台且通知开启时会把这条结果加入 Toast 队列。

通知去重以最新成员的开始时间区分重试，耗时却从最早成员的开始时间算到最后完成。旧的已完成成员因此把 60 秒前的时间带进了新一轮判定。[批次通知判定](../../crates/capstan-core/src/desktop/mod.rs#L153)

将以下探针临时保存为 `crates/capstan-core/tests/m4_2_review.rs`，运行 `cargo test --locked -p capstan-core --test m4_2_review fast_retry_under_threshold_does_not_inherit_the_previous_attempt`。实测断言失败，打印 `unexpected notices: [TransferNotice { kind: TransferCompleted, … }]`，退出码 101。

```rust
use capstan_core::{
    desktop::{DesktopTransfer, NoticeTracker},
    transfer::TransferState,
};
use std::time::{Duration, Instant};
use uuid::Uuid;

#[test]
fn fast_retry_under_threshold_does_not_inherit_the_previous_attempt() {
    let start = Instant::now();
    let batch_id = Some(Uuid::new_v4());
    let task = |state, attempt_started, finished| DesktopTransfer {
        id: Uuid::new_v4(),
        version: 1,
        batch_id,
        state,
        processed: 1,
        total: 1,
        attempt_started,
        finished: Some(finished),
        awaiting_reconnect: false,
    };
    let first_end = start + Duration::from_secs(1);
    let completed = task(TransferState::Completed, start, first_end);
    let mut retried = task(TransferState::Failed, start, first_end);
    let mut tracker = NoticeTracker::default();
    assert!(tracker.transfers(&[completed, retried]).is_empty());
    retried.attempt_started = start + Duration::from_secs(60);
    retried.finished = Some(start + Duration::from_secs(61));
    retried.state = TransferState::Completed;
    let notices = tracker.transfers(&[completed, retried]);
    assert!(notices.is_empty(), "unexpected notices: {notices:?}");
}
```
