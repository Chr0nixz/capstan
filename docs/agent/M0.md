# M0 技术验证阶段

> 状态：`accepted`（2026-10-17）；工程/数值证据与维护者实机范围已收口，见 [board](board.md) 和 [M1-B](M1-B.md)  
> 依据：[`docs/PLAN.md`](../PLAN.md) 第 2、3、5、6、8、9 节，以及 [`PRODUCT.md`](../../PRODUCT.md) 和 [`DESIGN.md`](../../DESIGN.md)  
> 阶段结论：M0 不发布版本；完成后才进入 M1 SSH 可用阶段

## 1. 阶段目标

M0 的目标是用一个可重复运行的 Windows 纵向切片，验证 Capstan 最关键、最容易推翻后续设计的技术假设。阶段结束时必须能在 Windows 11 上启动应用，打开本地 PowerShell 终端，并在同一个 Tauri/WebView2 窗口内完成可靠的输入、输出、尺寸变化和退出；随后还要验证 WSL 启动、Windows 原生窗口行为、字体和输入法，以及多标签压力下的资源释放。

M0 只回答“底层路径能否满足产品要求”这一个问题，不以功能数量或界面完成度作为进度指标。所有结论都要有测试记录、原始数据或维护者手测结果，不能用“看起来不卡”作为验收依据。

### 1.1 必须证明的结果

- 本地 PowerShell 可以通过优先选用的 ConPTY 实现启动、读写、调整尺寸并正常退出。
- 终端字节从 PTY 到 xterm.js 经过 Tauri Channel 时保持原始二进制、顺序和完整性，不经过 JSON 数组或 Base64。
- 输出合并器按“16 ms 或 64 KiB 先到”发送；累计未确认数据超过 1 MiB 时暂停读取，低于 256 KiB 后恢复读取。
- 前端以 `xterm.write` 的完成回调按实际处理字节数发送 ACK；取消、卸载和窗口关闭都能释放队列与任务。
- 输入、输出、resize、退出和错误路径均能结束，不留下后台读取任务、窗口事件监听器或 WebGL 资源。
- 只有可见终端挂载 xterm.js WebGL renderer；隐藏、销毁或切换标签后释放，并可再次挂载。
- WSL 优先通过注册表枚举发行版和默认发行版；注册表不可用、数据不完整或版本不兼容时使用受控的 `wsl.exe` 回退探测。
- ConPTY 捆绑运行时的版本、架构、加载路径、失败回退和再分发信息可记录；缺文件或启动失败时使用系统 ConPTY。未完成许可、签名和包内容核验前，不把捆绑文件作为发布内容。
- Mica、Snap hit-test、Cascadia Mono/中文回退、CJK/emoji、IME 候选框、高 DPI 和多显示器行为可在维护者设备上检查。
- 创建、切换和关闭 20 个标签后仍可继续渲染，且形成一份可复现的内存和句柄基线。

### 1.2 M0 完成后的产物

- 可运行的 M0 技术验证应用（开发模式即可，不打包发布）。
- A 门和 B 门的自动化测试、测试夹具和失败日志。
- 固定场景的性能基线：数据完整性、吞吐、输入响应、峰值内存、标签生命周期以及队列/IPC 背压数据。
- ConPTY 与 WSL 兼容清单，包含机器、Windows、WebView2、运行时、架构和实际选择的实现。
- 维护者手测验收记录；未通过的项目必须写明复现步骤、影响和下一步处理。
- M0 结束报告，明确“进入 M1”“补充验证后进入 M1”或“技术路径需要调整”三种结论之一。

## 2. 范围与边界

### 2.1 本阶段范围

| 区域 | M0 要做的内容 |

### 2.2 明确不在 M0

- SSH 连接、认证、主机指纹、连接池、SFTP、端口转发和 SSH Agent；这些属于 M1 或之后。
- Vault、密码派生、加密文件格式、备份、导入导出和 Windows Hello。
- 分屏、广播、命令片段、命令面板、服务器状态栏和传输队列。
- 远程终端、真实 OpenSSH 兼容性和 `CAPSTAN_TEST_SSHD` 测试；M0 可准备测试接口，但不得用假闭环代替后续集成测试。
- 安装包、自动更新、Authenticode 签名和发布渠道。
- 终端主题导入、完整 i18n 文案和产品级设置页面；验证所需的 UI 文案仍须走 i18n，不能在组件中硬编码。

## 3. 验收门设计

两道门必须按顺序完成。A 门失败时先修复终端链路，不能用 B 门的窗口体验工作掩盖数据通道问题；B 门失败时保留 A 门结果，并记录是否影响 M1 进入条件。

### 3.1 A 门：本地终端与 IPC

#### 场景 A1：启动和探测

1. 从受控探测器列出 PowerShell 5.1、PowerShell 7 及其可执行文件路径。
2. 按配置启动所选 shell；工作目录、环境变量和编码设置可追踪。
3. 首选经核验的 ConPTY 运行时；按绝对路径加载失败、架构不匹配或创建失败时回退到系统 ConPTY。
4. 在日志中记录实现选择、版本和失败原因，但不得记录终端内容或任何凭据。

#### 场景 A2：输入、输出和退出

- 输入 `echo`、方向键、退格、Ctrl+C、中文字符和 emoji，确认回显与顺序正确。
- 输出包含 ASCII、CJK、组合字符、emoji、ANSI 颜色、光标移动和超过单次合并阈值的数据。
- 通过 xterm.js 的 resize 触发 PTY 尺寸变化，执行能观察列数变化的命令确认生效。
- 正常退出 shell、关闭标签、关闭窗口和强制取消读取，分别确认进程、任务、Channel 和队列结束。
- 对启动失败、读写错误、Channel 传输错误和前端卸载进行可观测处理；错误不能导致应用无响应。

#### 场景 A3：二进制通道与背压

使用可重复的带序号字节模式，例如每个块含递增序号、长度和校验值，验证以下性质：

| 检查项 | 通过条件 |
| --- | --- |
| 原始传输 | Tauri Channel 的 payload 是二进制；不存在 JSON 数组或 Base64 中间格式 |
| 完整性 | 接收端校验值与发送端一致，零丢失、零重复、零乱序 |
| 合并 | 达到 16 ms 或 64 KiB 任一条件即发送；小块高频输出不会产生无界 IPC 调用数 |
| 背压 | 未确认累计值 `> 1 MiB` 时暂停 PTY 读取；降至 `< 256 KiB` 后恢复；暂停/恢复次数可记录 |
| ACK | `xterm.write` 完成回调按实际字节数 ACK；ACK 不得按消息条数估算 |
| 取消 | 终端卸载、窗口关闭、Channel 错误和测试取消都能唤醒等待者并释放资源 |
| 输入 | 键盘输入使用有界输入队列；队列满时有明确策略，不阻塞 UI 线程或无限增长 |

压力测试至少覆盖：持续输出 100 MiB、输出块大小变化、前端人为延迟 ACK、ACK 暂停后恢复、传输中关闭标签和重复启动/关闭终端。测试必须保存总字节、块数、序号范围、峰值队列、暂停时间、恢复次数、错误和最终状态。

#### 场景 A4：WebGL 生命周期

- 创建可见终端时挂载 WebGL renderer，并记录上下文创建结果。
- 切换到隐藏标签或非终端界面时释放 renderer；不可见终端不得继续占用 WebGL 上下文。
- 再次显示时重新挂载并恢复绘制，不重复注册输入、resize 或数据监听器。
- 关闭标签后确认 xterm、插件、renderer、Channel、PTY 和前端事件监听器都可回收。
- 在 WebGL 不可用时有明确降级行为，并记录是否使用 canvas renderer；降级不改变字节链路的正确性。

### 3.2 B 门：Windows 集成与压力

#### 场景 B1：WSL

1. 优先从注册表读取发行版列表、安装状态和默认发行版。
2. 注册表不可用、字段缺失、发行版信息不完整或 WSL 版本不兼容时，调用受控的 `wsl.exe` 探测；限制参数和输出解析范围。
3. 允许在指定目录启动；路径转换失败时给出明确错误，不静默改用其他目录。
4. 在无 WSL、无默认发行版、发行版已卸载和 `wsl.exe` 失败的机器上，应用仍能使用本地 PowerShell，并显示可理解的状态。

#### 场景 B2：原生窗口

- Mica 只作用于原生窗口边界；终端和内部工作区保持稳定的 Graphite 表面。
- 自绘标题栏的拖拽、最小化、最大化、还原和关闭命中区域正确。
- 最大化按钮覆盖原生 hit-test 后，鼠标悬停能显示 Windows 11 Snap Layouts；键盘操作仍可完成最大化和还原。
- 高对比度和 reduced-motion 设置不会导致窗口无法操作或信息仅靠颜色表达。

#### 场景 B3：字体、IME、DPI 和显示器

- 默认终端字体为 Cascadia Mono；中文回退到 Microsoft YaHei UI，可选字体路径按设计文档保留扩展点。
- 在中文输入法下，候选框位置与光标对应，组合中的文字不会提前提交或错位。
- 检查 CJK 宽度、emoji、组合字符、等宽列对齐和光标移动。
- 在 100%、125%、150% 等常见缩放以及不同 DPI 的多显示器之间移动窗口，终端列数、字体和 hit-test 均保持正确。
- 记录 WebView2 版本、显示器分辨率/DPI、字体实际命中情况和发现的问题。

#### 场景 B4：20 标签压力

固定机器、窗口尺寸、WebView2 版本和输出脚本，重复执行以下循环：

1. 创建 20 个本地终端标签，至少包含 PowerShell 和 WSL（若测试机提供 WSL）。
2. 轮流切换每个标签并产生少量输出，保持一个标签持续输出。
3. 关闭标签，再次创建并切换同样数量的标签。
4. 重复至少 3 轮，记录每轮结束后的工作集、私有字节、句柄数、WebGL 上下文数、PTY 进程数、队列积压和输入响应时间。

通过条件是所有可见终端继续渲染，关闭的标签不再产生输出或增长资源，PTY 和监听器数量回到预期范围；内存绝对值不预设发布承诺，但必须形成后续回归可比较的基线。

## 4. 开发计划

开发顺序以依赖为准。每个阶段完成后先运行本阶段测试并记录结果，再进入下一阶段；如果发现底层能力不满足要求，要更新风险记录和决策记录，不通过临时 JSON 或无界队列绕过验收。

### 阶段 0：准备与可观测性

- 建立 Rust workspace、`crates/capstan-pty`、`src-tauri` 和 `ui` 的最小构建骨架；保持 crate 不依赖 Tauri。
- 固定 Rust、Node/pnpm、Tauri、xterm.js 和关键依赖版本，确认许可证符合 GPL-3.0-or-later。
- 定义统一的终端会话状态：启动中、运行中、退出中、已退出、错误和已取消。
- 定义结构化测试事件与指标模型。事件只记录会话标识、字节数、时间、队列水位、实现版本和错误代码，不记录终端内容。
- 定义取消令牌、资源所有权和关闭顺序：前端卸载/窗口关闭 → 取消 Channel 与输入输出任务 → 关闭 PTY → 释放 renderer 和监听器。

**输出：** 可构建空壳、指标字段说明、错误码和资源生命周期图；不开始性能结论。

### 阶段 1：本地 shell 与 PTY

- 实现 PowerShell 5.1/7 探测，处理路径不存在、权限不足和重复项。
- 接入 `portable-pty`，封装启动、读、写、resize、关闭和退出状态。
- 验证捆绑 ConPTY 的目录布局、x64/ARM64 选择、绝对路径加载和系统回退；把许可/签名核验结果作为单独清单，不把猜测写成结论。
- 编写 Rust 单元测试和 Windows 集成测试，覆盖启动失败、resize、正常退出、强制取消和重复关闭。

**出口条件：** 不经过 Tauri 时，PTY 适配层能在 Windows 测试机上可靠完成 A1/A2 的底层操作。

### 阶段 2：输出合并器与 Channel

- 实现每个可见终端独立的有界输出队列和输入队列。
- 实现 16 ms/64 KiB 合并器、字节计数、ACK 等待、1 MiB 暂停和 256 KiB 恢复。
- 使用 Tauri Channel 传递原始二进制 payload；明确 Rust 到前端的类型边界，禁止由通用命令返回 `Vec<u8>` 让 Tauri 做 JSON 序列化。
- 处理 ACK 超时、重复/延迟 ACK、Channel 错误、窗口关闭和终端卸载；确认所有等待都能取消。
- 增加带序号和校验的压力夹具，保存可机器解析的结果。

**出口条件：** A3 全部自动化测试通过，100 MiB 固定场景无丢失/乱序，背压可重复触发和恢复，取消后资源回收。

### 阶段 3：xterm.js 与前端生命周期

- 创建最小终端组件，接入 fit、unicode11、web-links、search 和 webgl 所需的基础插件边界；M0 只实现输入、输出、resize 和可见性管理。
- 将 `onData` 接入有界输入队列，将 `xterm.write` 完成回调接入 ACK；不在 React 状态中保存终端字节流。
- 以可见性为条件挂载/卸载 WebGL renderer，避免隐藏终端长期占用上下文。
- 处理组件卸载、标签关闭和 Tauri 窗口销毁，确保监听器只注册一次并全部移除。
- 验证中文、emoji、ANSI 控制序列、粘贴和 Ctrl+C 等基础交互；多行粘贴安全确认属于后续产品功能，不在 M0 扩大范围。

**出口条件：** A 门端到端场景通过，手动输入和压力输出同时存在时 UI 仍可响应。

### 阶段 4：WSL 与 Windows shell 集成

- 实现注册表枚举适配器，隔离 Windows API 读取错误和字段解析错误。
- 实现受控 `wsl.exe` 回退探测，固定允许的参数和超时，拒绝将任意命令字符串暴露为通用执行接口。
- 将 PowerShell、WSL 和失败状态映射到统一的本地终端启动接口。
- 增加无 WSL、无默认发行版、注册表失败、版本不兼容和指定目录无效的测试夹具；在非 Windows 环境明确跳过并说明原因。

**出口条件：** B1 的正常、回退和失败场景都有自动化结果，错误不影响 PowerShell 启动。

### 阶段 5：窗口、字体和显示适配

- 实现自绘标题栏与 Mica 的最小窗口壳，验证拖拽、系统按钮、原生 hit-test 和 Snap Layouts。
- 配置 Cascadia Mono、Microsoft YaHei UI 回退和可选字体入口，检查终端字符单元宽度。
- 在真实 Windows 设备上检查 IME、CJK/emoji、高 DPI、多显示器、高对比度和 reduced-motion。
- 将维护者发现的问题按“阻断 M0 / 进入 M1 前修复 / 后续体验优化”分类，不用截图替代复现信息。

**出口条件：** B2/B3 手测清单完成，阻断项关闭或得到维护者明确的延期决定。

### 阶段 6：压力基线与阶段收口

- 固定测试机器、Windows 版本、WebView2 版本、显示器参数、构建配置和输出脚本。
- 运行 100 MiB 终端数据场景以及 20 标签生命周期场景，至少重复 3 次，保存原始结果和汇总表。
- 比较冷启动、持续输出、输入响应、峰值内存、句柄、WebGL 上下文、PTY 进程和队列水位；记录测量误差和未测量项。
- 建立 ConPTY/WSL 兼容清单，标记系统版本、架构、实际选用路径、回退路径和已知限制。
- 逐项完成本文件第 7 节验收清单，写 M0 结束报告和 M1 入口条件。

**出口条件：** B4 结果可复现，维护者完成手测，M0 结论和遗留风险均已记录。

## 5. 测试与验证计划

### 5.1 自动化测试矩阵

| 层级 | 重点 | 环境 | 结果要求 |
| --- | --- | --- | --- |
| `capstan-pty` 单元测试 | shell 探测、状态转换、尺寸参数、错误映射、取消 | Windows CI / 本地 | 不依赖真实用户配置；失败信息含错误码 |
| PTY 集成测试 | PowerShell 启停、读写、resize、退出和重复关闭 | Windows CI | 进程和句柄按预期结束 |
| IPC/合并器测试 | 阈值、顺序、校验、ACK、背压、取消、超时 | 本地 + Windows CI | 固定字节模式无丢失/重复/乱序 |
| 前端 Vitest | 输入队列、可见性、ACK、监听器清理、状态转换 | Node | 不依赖真实 WebView2；覆盖取消和重复挂载 |
| Tauri 契约 smoke test | Channel payload 类型、事件/命令参数和错误路径 | Windows | 不允许退化成 JSON 字节数组 |
| WSL 适配测试 | 注册表成功/失败、`wsl.exe` 回退、无发行版、路径错误 | Windows；按环境跳过 | 跳过原因明确，失败不吞错 |
| 性能夹具 | 100 MiB 输出、延迟 ACK、20 标签循环 | 固定 Windows 设备 | 保存原始数据、版本和配置 |

### 5.2 数据完整性检查

性能夹具不得只测吞吐。每个输出块附带序号、长度和校验值；测试结束校验总字节、首尾序号、缺失/重复序号和校验失败数。输入测试记录发送字节数、PTY 观察到的回显和输入延迟。所有结果写入不含终端正文的 JSON 或 CSV，便于后续 M1/M2 比较。

### 5.3 必须运行的工程检查

在 M0 交付前运行并记录：

```text
cargo fmt --all -- --check
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
pnpm -C ui typecheck
pnpm -C ui test
```

若某项因脚手架尚未建立而不能运行，必须在结束报告中说明缺失原因和替代验证，不把未执行写成通过。

## 6. 性能基线记录格式

每次基准记录以下元数据：

- Git 提交或工作区版本标识、Rust/Node/pnpm/Tauri/xterm.js 版本。
- Windows 版本、CPU、内存、架构、WebView2 版本、ConPTY 实际版本和加载路径。
- 显示器数量、分辨率、缩放比例、窗口尺寸、主题和字体。
- 测试场景、输出总字节、输出块大小分布、运行时长和重复次数。
- 端到端吞吐、首字节时间、输入响应时间（中位数和高分位）、峰值内存、句柄数、PTY 进程数。
- Rust 队列、IPC 在途和前端待处理字节的峰值与时间序列；暂停/恢复次数和累计暂停时长。
- WebGL 上下文数、终端标签数、关闭后残留任务/监听器/进程数。
- 数据完整性计数、错误码、取消耗时和是否需要人工干预。

M0 不预先设定“内存低于某个数字”或“达到某个 MB/s”作为发布门槛。首轮数据用于建立基线；后续里程碑再基于同一机器和场景设定回归阈值。

## 8. 风险、决策和升级路径

| 风险/发现 | M0 处理方式 | 升级条件 |
| --- | --- | --- |
| Tauri Channel 无法满足原始二进制或背压语义 | 在 A 门保留端到端复现，评估替代 IPC 传输并更新方案 | 不得退化为 JSON 数组或 Base64；未解决则不能宣布 A 门通过 |
| `portable-pty` 无法安全加载捆绑 ConPTY | 先验证版本、架构、路径、签名和系统回退 | 只有确认缺少明确能力后，才提交自写封装的成本和兼容性评估 |
| ConPTY 包许可或再分发条件不清 | 只做本地加载实验，不随应用发布捆绑文件 | 未完成核验前不进入安装包和发布流程 |
| xterm.js WebGL/IME 在 WebView2 中异常 | 保留最小可复现测试，优先评估上游修复或补丁 | 若影响输入、CJK 或资源释放，阻断 B 门 |
| WebView2 内存高于预期 | 记录实测值，区分 WebView2、xterm、IPC 和应用自身 | 先建立基线；不得在没有数据时承诺安装后或运行时大小 |
| WSL 注册表结构或版本差异 | 适配器失败时进入受控 `wsl.exe` 回退 | 两条路径均不可用时保留 PowerShell，并记录支持范围 |
| 真实设备手测无法自动化 | 由维护者按清单验收，记录设备和复现步骤 | 阻断项必须在 M0 结束报告中明确处理决定 |

所有会改变 [`docs/PLAN.md`](../PLAN.md) 中架构、验收标准或里程碑顺序的决定，先与维护者确认，再同步更新 PLAN 的决策记录；本文件只记录执行细节和验证结果。

## 9. M0 退出条件与 M1 入口

### 9.1 退出条件

M0 只有在以下条件全部满足时才能标记完成：

1. A 门的输入、输出、resize、退出、原始二进制、完整性、背压、ACK、取消和 WebGL 生命周期测试通过。
2. B 门的 WSL 正常/回退路径、Mica/Snap、字体/IME/DPI 和 20 标签压力检查完成。
3. 性能数据和兼容清单可由另一位开发者按记录复现，或明确标注无法复现的环境限制。
4. 工程检查已运行并记录；失败项有具体原因和修复计划。
5. 维护者手测清单已签字或逐项留下结论；阻断项没有被“已知问题”掩盖。
6. 没有新增违反安全边界的通用 shell、fs、远程内容或凭据暴露接口。

### 9.2 进入 M1 前必须保留的接口

- 本地终端和后续 SSH 终端共用的字节流、输入队列、resize、取消和可见性生命周期接口。
- 可替换的终端后端接口，使 SSH 通道能复用同一套 Channel、ACK 和背压验证。
- 统一的连接/终端状态与错误模型，不把 PTY 特有错误写死在前端。
- 指标和压力测试夹具，可在 M1 加入 SSH shell、重连和多标签场景。

M0 结束后，下一阶段文档应以本文件的基线和遗留风险为输入，进入 Vault、主机指纹和单条 SSH shell 闭环；不得重新定义已通过的终端字节传输和取消语义。
