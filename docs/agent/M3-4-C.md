## C1–C4 复验

| 问题 | 独立检查与实际结果 | 结论 |
| --- | --- | --- |
| C1：远程撤销失败被误报停止 | 拒绝时保留 Failed / remote_forward_rejected、端点注册及租约；配置编辑、删除和覆盖导入受阻；重试成功后监听端口释放。超时后继续等待同一请求的迟到确认，服务端撤销请求计数为 1 | 原问题关闭 |
| C2：首次 shell 失败后自动隧道无监督 | 采纳连接后先安装监督，再启动自动隧道和 shell；PTY 拒绝与取消均释放尝试 owner，自动隧道保有的连接可断线重建，代次递增 | 原问题关闭 |
| C3：慢速远程启动阻塞其他隧道停止 | 释放配置/连接锁后等待启动结果；手动、自动慢启动期间均可停止 sibling；启动中的远程隧道也可取消并等待回收确认 | 原问题关闭 |
| C4：主机删除失败会先关闭本地 sibling | 按远程优先、ID 稳定排序处理；新增测试以四条同主机隧道验证首次远程撤销拒绝后，本地 sibling、后续远程 sibling、Vault revision 和配置仍保留。新增用例和原先间歇失败的用例单独重跑均通过 | 原始复现关闭 |

修复范围按 B 的说明核对：远程撤销失败前不会停止本地/SOCKS5 sibling，尚未处理的远程 sibling 保持运行。批量删除仍逐项停止；若较早的远程撤销已成功，较晚的撤销失败不会自动恢复之前的远程监听。该行为不提供整批运行时的原子回滚保证，本轮没有引入这一额外契约。
