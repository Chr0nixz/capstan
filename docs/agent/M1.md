## 1. 阶段目标与交付结果

M1 的目标是让维护者可以用 Capstan 完成日常 SSH 工作：创建和解锁加密库，保存主机，在核验服务器指纹后连接 Linux 服务器，使用密码、私钥或 Windows SSH Agent 认证，在多个标签中工作，并在重启应用或换一台机器后恢复自己的配置。

本阶段必须同时证明连接可用、数据可靠、凭据边界成立。单次 SSH 登录成功、加密函数通过往返测试或安装程序可以启动，都不足以代表 M1 完成。

### 1.1 必须实现的用户结果

- 未解锁 Vault 时仍可打开本地 PowerShell/WSL；查看保存的主机、管理凭据和建立新的 SSH 工作流需要解锁。
- 正确主密码可以解锁；错误密码、被篡改文件、未知版本和资源消耗异常的文件头都得到明确处理，原文件不会被覆盖。
- 首次连接显示目标、主机密钥算法和指纹，用户确认并成功保存信任记录后才进入认证；指纹变化直接阻断，显示新旧对比。
- 密码、导入/文件引用私钥、Windows OpenSSH Agent 和 Pageant 的正常及失败路径可复现；远程凭据明文不进入 WebView。
- 主机和分组可增删改查，支持收藏、标签与搜索；配置和信任记录加密保存，应用重启后可恢复。
- 同一兼容配置的多个 SSH 标签共用一条连接，每个标签拥有独立 shell 通道；不兼容的身份、信任或转发策略不得复用。
- 本地和 SSH 终端共用现有原始二进制 Channel、ACK、背压、输入队列和显示生命周期；搜索、resize、关闭和异常退出均可用。
- Vault 支持改主密码、自动锁定、最近 3 个有效加密备份，以及独立口令的 `.cbak` 导出、预览和合并/覆盖导入。
- 提供 Windows 用户级 NSIS 安装包与便携 zip，明确数据目录、WebView2 前置条件、实际体积和已验证架构。

### 1.2 最终交付物

交付物包括 M1 实现、跨语言契约与回归测试、Vault 格式及恢复说明、SSH 认证/Agent 兼容清单、性能比较原始数据、维护者手测记录，以及可重复构建的 v0.1 候选包。发布到 GitHub Releases、创建 tag、提交或推送仍需维护者明确要求，不由完成本计划自动触发。

## 4. 开发前必须固定的契约

以下是实现和审查依据，具体 Rust 类型及命令命名在任务 M1-01 中冻结。涉及 PLAN 改动的决定按仓库规则另行确认。

### 4.1 领域边界与资源所有权

| 所属位置 | 必须负责 | 不应承担 |
| --- | --- | --- |
| `crates/capstan-vault` | 文件格式、KDF/密钥生命周期、加解密、数据模型、迁移、事务写入、锁定、备份/导入导出 | Tauri、React 状态、SSH 网络传输 |
| `crates/capstan-ssh` | 认证与信任流程、连接状态/连接池、通道租约、Agent、异步 SSH 适配 | 终端渲染、Vault 文件格式、复制 PTY 实现 |
| `crates/capstan-terminal` | 后端无关的字节预算、帧协议、输入和输出生命周期、状态、取消与任务回收 | 依赖 SSH/PTY/Tauri 或判断认证与主机信任 |
| `src-tauri` | 命令/事件 DTO、调用来源与能力检查、Channel、窗口及原生对话框的平台适配 | 加密算法、连接池规则、文件事务、会话生命周期编排 |
| `ui` | 解锁入口、脱敏模型、确认交互、树/标签/搜索、状态展示与 i18n | 密码/私钥读取、密钥派生、连接池所有权、持久化终端字节 |

SSH 通过 Rust 侧凭据解析和信任存储接口取得能力，由 Vault 适配器完成读写。接口的领域规则留在 crate 内，Tauri 只做接线。不要为了复用而使 Vault 依赖 SSH，或使共享终端反向依赖具体后端；也不在本阶段引入一个无明确职责的通用服务框架。

标识必须分开：

| 标识 | 生命周期与用途 |
| --- | --- |
| `HostId` / `CredentialId` / `GroupId` | Vault 中持久化实体；不能直接等同于 TCP 连接或标签 |
| `ConnectionId` | 一次真实 SSH 传输连接；同连接上的多个 shell 共用它 |
| `ConnectionAttemptId` | 一次连接/认证/指纹确认尝试；支持取消、超时和拒绝迟到确认 |
| `TerminalSessionId` | 一个本地终端或 SSH shell 通道；沿用既有输入、ACK、resize、关闭入口 |
| `TabId` | 前端布局身份；切换语言、可见性和主机排序不能重建会话 |

`PaneId` 和窗格树留到 M3。连接代次与主机/凭据修订号用于拒绝旧事件和错误复用，不用标签数量推算连接数。

### 4.2 Vault 格式、事务和锁定

- 按 PLAN 使用 Argon2id 派生 KEK、随机 DEK 和 XChaCha20-Poly1305；格式包含 magic、封装/schema 版本、KDF 标识及参数、salt、DEK 包装信息与数据 nonce/ciphertext。
- 格式规格明确整数编码、长度界限、允许字段、认证数据覆盖范围和版本拒绝规则。必须同时满足“格式/KDF 元数据受认证保护”和“改主密码只重包裹 DEK”；不能因 AAD 设计导致修改口令破坏数据认证。
- 读取先限制文件大小、字段长度及 KDF 资源消耗，再分配大块内存或执行派生。默认参数、允许的最小值和最大值在目标设备测量并审查后冻结，不把未测量数值写成安全结论；超过上限明确拒绝，不静默降级。
- salt、DEK 和 nonce 使用密码学安全随机源；并发写入、备份与导出均需覆盖 nonce 管理。不得直接拼接或修改密文实现合并。
- 库 schema 与封装版本分别管理。迁移先验证源文件，在内存中转换，成功后事务提交；未知版本、迁移失败或损坏不得写回原文件。首版暂无历史用户数据时，用测试中生成的旧 schema 夹具验证迁移机制，不声称兼容不存在的已发布版本。
- 单个库只有一个写入协调者；覆盖多窗口/多进程竞争、修订冲突和丢失更新。使用同目录临时文件、flush、文件同步和平台适配的原子替换；目录同步按平台能力实现并记录限制。
- 启动时区分有效主文件、未完成临时写入和可恢复备份。恢复必须做格式及认证校验，不按时间戳直接覆盖；主文件异常时提供明确恢复选择。
- 备份保留最近 3 个验证通过的加密版本，不让坏文件淘汰好备份。改主密码后的备份口令策略需写入格式/恢复说明并测试，不能声称新密码会自动使历史副本失效。
- 默认空闲 30 分钟锁定，可关闭。空闲由本地用户交互计算，远端持续输出不能一直延长解锁；系统长时间挂起后重新检查期限。
- 锁定清理应用持有的 DEK/KEK、解密模型及凭据临时缓冲，并失效挂起的认证/指纹确认。默认保留已建立的终端交互；启用“锁定时断开连接”时关闭全部 SSH 连接及通道并等待本地任务回收，本地 PTY 不受影响。
- 锁定后不解密凭据、不新建 SSH 工作流，前端清理主机树和编辑表单等解锁态缓存。既有终端屏幕仍可能含主机信息和内容，必须按 PLAN 清楚表达该边界。

### 4.3 凭据录入与主机信任

远程密码、私钥正文及私钥口令不得进入 React 表单、Zustand、invoke 参数或通用事件。M1-01 必须落实一个由 Rust 管理的原生凭据录入/文件选择路径：前端只发起操作并取得 `CredentialId` 或取消/错误；库、Agent 和文件解析在 Rust 侧完成。不能用“只在提交时短暂经过前端”代替此规则。

Vault 主密码允许经专用初始化/解锁/改密流程提交 Rust，但不进入持久状态、通用事件或日志；使用后及时清理 UI 控件，Rust 所有的秘密缓冲使用 `secrecy`/`zeroize`。`.cbak` 独立口令沿用 Rust 管理的原生录入路径，不增加前端明文口令通道。原生录入方案与当前 `unsafe_code = deny` 的兼容方式要在实现前核实。

主机校验按以下顺序执行：

1. Rust 读取已解锁的主机快照，固定地址/端口、身份、策略和修订号；建立连接尝试并在认证前检查服务端公钥。
2. 信任记录按规范化目标与端口索引，并保存公钥、算法、指纹和首次信任时间。别名、IPv6 和非默认端口必须有测试；显示用名称不能成为唯一信任键。
3. 首次未知主机产生与本次尝试、公钥及 Vault 解锁代次绑定的确认请求。用户取消、超时、关标签、锁库或编辑目标时，尝试结束；迟到确认不可用于新连接。
4. 确认后先事务保存信任记录，再继续认证。持久化失败就停止，不把“本次已点确认”当作已保存。
5. 已有信任与本次公钥不匹配时直接阻断并显示新旧算法/指纹。算法改变不能绕过已有信任校验；不提供连接弹窗里的“忽略并继续”。
6. 合法换钥通过独立、明确的信任管理操作核验并更新，随后重新连接；旧连接尝试不能被恢复。信任修改与导入冲突都会失效相关的待确认操作和后续复用资格。

认证失败、连接失败与密钥不匹配使用不同稳定错误码。诊断只记录不透明 ID、阶段、耗时和错误码；不记录凭据、终端内容、启动命令、完整 Agent 身份注释或解密后的 Vault 模型。

### 4.4 SSH 异步后端与连接池

- SSH 直接使用 tokio/russh 的异步通道；在 `capstan-terminal` 增加异步后端接入并复用公共会话生命周期。禁止为适配阻塞 `Read`/`Write` 而在运行时线程 `block_on`，或为每条 SSH 流再开无界线程/缓冲队列。
- 继续执行 16 ms/64 KiB 合并、积压 `> 1 MiB` 暂停、`< 256 KiB` 恢复、单块最大 64 KiB，以及 `xterm.write` 回调 ACK。现有应用输出预算最大越界一个块；另行记录 russh 通道窗口和库内部缓存，不能将应用预算当作总 RSS 上限。
- SSH 读取、扩展数据、窗口调整及控制消息都纳入有界设计。某个 shell 等待 ACK 时，不能阻塞整个 SSH 连接的消息分发，导致其他 shell、关闭或协议控制消息停止；必须用两个通道的压力测试证明隔离。
- 输入保持有界，包含正在写入的数据。结果不确定时清空旧输入并结束对应输入路径，不自动重试；resize 与 close 不等待同一把写入锁。
- 正常 EOF 排空已接受输出；分别处理 EOF、exit-status、exit-signal、channel-close 和传输断开，允许没有退出码，不能把它伪造为成功退出。终态只发布一次，最后一段输出仍按既有控制器契约送达。
- 关闭标签只释放自己的 shell 和连接租约；关闭窗口等待所有启动尝试、通道、后台任务与连接清理。只保证本地资源和协议通道回收，不声称可终止任意远端后代进程。

连接池使用规范化复用键，至少包括目标地址/端口、用户名、认证身份及其修订、Agent 身份选择、跳板/代理路径和影响安全的策略。信任版本、Agent 转发授权等不兼容时不复用；密钥或口令明文不得作为 key 或日志字段。

- 同 key 并发连接合并为一个建连/认证过程。取消一个等待者不取消其他有效等待者，最后一个等待者取消则回收启动任务。
- 一个连接持有独立通道租约集合，租约模型可以在 M2/M3 加入 SFTP/隧道，不实现这些未来功能。
- 最后一个通道释放后保留 30 秒；新租约取消空闲关闭，超时才关闭。定时器和连接代次绑定，旧计时器不得关闭新连接。
- Vault 锁定阻止新的连接/认证入口；连接断开后所有旧 shell 进入结束状态并保留屏幕回滚。显式再次连接使用新 ID，不重新使用旧输入队列。
- 状态至少区分连接中、等待信任、认证中、已连接、关闭中、已关闭和失败；为 M3 预留重连状态，但 M1 不进入自动重连流程。

### 4.5 前端与 IPC

- 将 `TerminalLaunch` 扩展为本地/SSH 可辨识联合；SSH 启动只携带 `HostId` 和必要的尝试标识。启动结果区分本地运行时信息和 SSH `ConnectionId`，不为 SSH 伪造 ConPTY 元数据。
- 通用输入、ACK、resize、stop 命令继续按 `TerminalSessionId` 工作。主机 CRUD、Vault、信任确认和连接状态使用集中 DTO、稳定错误码及 Rust/TS 共同 fixture。
- 命令逐项列出来源窗口、参数范围、锁库条件和能力。凭据录入、文件导入导出使用专用命令及受控选择结果，不开放任意文件读写或通用 shell/fs 插件。
- Zustand 只保存可序列化的解锁态主机视图、布局和状态；不保存凭据、终端字节、xterm 实例或网络句柄。切换语言、排序和可见性不得重启连接。
- 连接等待、取消、认证失败、密钥变化、锁定、文件冲突和导入结果都提供 `zh-CN`/`en` 文案；安全状态同时用文字和视觉信号表达，遵守现有 DESIGN。
- 终端搜索提供 Ctrl+Shift+F、前后查找、大小写与正则选项；无效表达式可恢复，关闭搜索恢复终端焦点，不将查询内容写入日志。
- 开放远端终端前落实 PLAN 的终端安全策略：OSC 52 写剪贴板默认询问、读剪贴板一律禁止，多行粘贴确认并保持 bracketed paste；http(s) 与其他链接分开处理，非 http(s) 需确认。此项属于 SSH 可用的安全闭环，不能拖到通用右键菜单阶段。

### 6.1 M1-01：先冻结接线与数据契约

新增独立 Vault/SSH crate 并加入 workspace，保持无 Tauri 依赖。核实 russh 的 ring 特性、Agent 能力、所有新增依赖的精确版本、MSRV 和 GPL-3.0 兼容许可；记录实际版本，不直接沿用网上示例或假定 API 已存在。

形成可审查的 Vault 格式说明、命令/事件表、凭据录入原型、状态转换表和资源所有权图。接口至少覆盖初始化/解锁/锁定、脱敏主机 CRUD、原生凭据录入、信任挑战回应、SSH 启动取消，以及既有通用终端命令。错误只返回稳定代码和已批准的非秘密字段。

文件引用私钥的可读路径与导入/导出目标通过专用本机选择流程取得；在读取/提交时重新检查文件类型、大小和权限，取消不留明文临时文件。记录生产包能力与开发配置差异，避免发布 CSP 继续放行 Vite 开发端口。

### 6.2 M1-02～06：按最短路径打通 A 门

先独立测试 Vault，再将密码凭据和主机信任接入单条 SSH 连接，最后接上真实终端与 UI。不要在密码/指纹闭环之前完成复杂树形导航、连接池优化或安装界面。

密码由原生入口交给 Rust，写入 Vault 后认证层只使用凭据引用。认证失败结束本次尝试，用户修改凭据后重新发起；不自动轮流尝试所有保存身份。未知主机确认和认证取消必须能在没有 Tauri 的测试中驱动。

异步终端扩展先用可控假后端覆盖 EOF/取消/错误的各种顺序，再接 russh 服务端。随后运行真实 Windows/WebView2/WSL 闭环，记录原始数据和设备条件；A 门修复完毕后才推进 B 门。

### 6.3 M1-07～09：管理、认证和连接复用

主机模型覆盖名称、地址、端口、用户名、认证引用、标签/分组/收藏，以及 PLAN 中的默认目录、启动命令、编码和终端配色。字段必须有实际行为与测试，不能只提供无法生效的表单。支持的编码及远端目录设置方式形成明确矩阵；未知值拒绝，不能默默当作 UTF-8 或依赖任意 shell 字符串拼接。

启动命令是用户明确保存的配置，只在新建 shell 时按配置执行一次，不因状态刷新、连接复用或失败重试而重放。修改主机/凭据不隐式改写运行中的 shell；新连接使用新修订。删除组须处理子节点，删除主机/凭据须检查引用并确认影响，不能静默删除共享凭据或信任。

私钥测试按 OpenSSH/PEM、加密/未加密、受支持算法和损坏/不支持格式构建矩阵；测试时生成密钥。文件引用不等于已导入 Vault，重启和跨机导入时必须重新验证可用性。

Agent 支持 Windows OpenSSH 命名管道和 Pageant 的实际可用入口，记录实现/版本。身份选择持久化稳定标识，不保存私钥；Agent 不可用或拒绝签名时提示并退出，不静默换认证方式。Agent 转发默认关闭，按主机明确开启，纳入复用隔离；测试关闭后远端不能使用转发能力。

连接池使用可控制时钟和可注入连接工厂测试计数及竞态，包含认证进行中取消、最后租约释放时新租约到来、策略修改后打开标签。不得只检查 UI 显示的连接数。

### 6.4 M1-10～11：数据迁移和完整体验

`.cbak` 使用独立口令和版本化加密封装，具备同样的格式/大小/KDF 防护。导入先解密校验并生成冲突预览，再一次事务提交；错误口令、用户取消或提交失败保留原库。

合并要处理 ID 重映射、凭据/主机/分组引用、重名和重复目标；主机指纹冲突单独阻断，不用“最后写入覆盖”扩大信任。覆盖前保留有效备份；正在使用的旧模型与连接复用资格按修订失效，不能把活动 shell 悄悄绑定到导入后的另一台主机。

跨机测试使用独立目录和另一真实机器：导入型私钥随加密备份恢复；文件路径引用、Agent 入口和本机偏好按实际可用性重新确认。所有预览和错误结果不返回秘密字段。

完成 Ctrl+Shift+F 搜索、焦点回归、连接/锁定/错误状态、中英切换，以及无 Vault、空主机列表、Agent 缺失和只使用本地终端的工作流。复查渲染/订阅不会因为主机状态频繁变化而重建。

### 6.5 M1-12～13：打包、回归和验收

安装模式写入 `%APPDATA%\Capstan\`；便携模式使用 exe 旁明确标识的可写数据目录，启动即验证，不可写时报错。模式识别不能因为偶然存在同名文件或工作目录不同而错误选择另一份库。升级/卸载不得静默删除 Vault，保留与删除行为写入说明并手测。

补齐实际可用的开发/构建命令及固定版本工具链，CI 执行 fmt、clippy、Rust/前端测试、运行时构建、`cargo deny` 和前端许可证检查。更新 `THIRD_PARTY_NOTICES.md`，保留 portable-pty 补丁说明及对应源码；只打包已核验的 ConPTY 二进制和 companion 文件。

Windows x64/ARM64 分别记录构建与运行状态，不把交叉编译通过等同于实机支持。NSIS 用普通用户测试安装/升级/卸载；便携包测试移动目录、只读位置和全新用户。记录压缩下载大小、安装后大小及 WebView2 安装/缺失行为，不写预设体积承诺。

v0.1 暂无 Authenticode 签名，发布说明明确该事实；本阶段不启用自动更新。提供中英文 README、CONTRIBUTING、SECURITY.md、CHANGELOG，以及实际构建/恢复说明。是否发布由维护者在候选包和验收结果可审查后决定。

### 7.2 真实 OpenSSH 与性能

- 通过 `CAPSTAN_TEST_SSHD` 指定测试目标，例如 `user@127.0.0.1:2222`；未设置时明确报告跳过。认证材料由 Rust 测试支持设施安全取得，不提交真实密钥，不输出密码。主机变化/破坏场景在临时服务端完成，不修改维护者常用 sshd 的密钥。
- 覆盖密码、公钥、Agent（环境提供时）、PTY/resize、Unicode、退出和多 shell。真实 Windows OpenSSH Agent 与 Pageant 分别记录；模拟器通过不能冒充两者都验收。
- 在 M0 相同机器、窗口尺寸和 WebView2 条件下，记录本地回归和 SSH 100 MiB 模式输出；增加服务端版本、CPU、RTT、加密算法及连接/通道数量。
- 20 标签至少包含同连接多个 shell、不同身份隔离和本地/SSH 混合，重复至少 3 轮；记录吞吐、输入响应中位数/高分位、峰值内存、句柄、WebGL、队列及关闭后残留任务。
- 另测一个延迟 ACK 的 shell 与同连接正常交互 shell，证明流控与取消相互隔离。数据必须零丢失/重复/乱序；取消场景按允许丢弃的契约单独统计。
- M1-01 根据已验收 M0 基线确定并记录回归阈值及误差范围，运行后不能修改阈值来使结果通过。M0 基线尚缺失时，不预填吞吐/内存数字或宣称性能达标。
- KDF 独立记录参数、设备、耗时分布和峰值资源，支持默认值选择。性能产物只含合成数据的计数/校验、环境及稳定 ID，不含真实主机清单或终端正文。

### 7.3 工程检查

cargo clippy --workspace --all-targets --features tauri-runtime -- -D warnings

### 9.3 M1 完成与 M2 入口

只有同时满足以下条件，M1 才可标记完成：

1. M0 前置条件有有效验收结论；A/B 门所有必需项通过，必要延期已由维护者确认并同步方案。
2. 三类认证、信任阻断、重启恢复、连接复用隔离、Vault 写入恢复与跨机导入都有自动化及对应真实环境证据。
3. 本地/SSH 共用终端契约不回归；性能数据可复现，资源回收和 M0 比较结论清楚。
4. 凭据边界、锁定策略、严格 CSP、最小命令能力、依赖许可和敏感日志检查通过。
5. 候选安装/便携包、构建说明、恢复说明、兼容清单和维护者手测结果完整，没有隐藏的阻断项。

进入 M2 时应保留独立连接池、通道租约、Vault 凭据/信任服务，以及稳定的终端会话契约。SFTP 应在现有兼容连接上开新通道，不通过终端标签重新创建 SSH 连接，也不将文件传输队列塞进终端输出链路。
