## 初审发现

### P2 采集先占满 `MaxSessions` 时，后续 shell 和 SFTP 被拒

在隔离的 Linux 测试 sshd 上设置 `MaxSessions 2` 并启用 SFTP。连接 Capstan 后，先让一个 shell 的状态栏完成采样，再在同一连接打开 SFTP 或第二个 shell。采集暂停时仍持有 exec，因此切到本地标签或最小化也不会释放名额。原有测试覆盖的是采集申请名额时被拒的顺序。

初审用真实 sshd 和 Capstan 的连接池复现了这一顺序。先打开一个 shell，再通过 `open_exec("sh")` 启动一个等待 stdin 的通道。在同一租约上，第二个 `open_shell` 返回 `Connection`，`open_sftp` 返回 `Unavailable`。关闭 exec 后，SFTP 在同一传输上打开成功。[加固后的回归测试](../../crates/capstan-core/src/server_status/tests.rs#L456)

### P3 带数字列样式的文件系统源名会导致磁盘详情误报

在隔离的挂载命名空间中运行以下命令，需要 root 权限。GNU `df` 输出的源名保留了空格及其中的数字。解析器将源名中的 `10 2 8 20%` 当作容量列，后面的真实容量和挂载路径一起变成挂载点名称。[磁盘解析](../../crates/capstan-core/src/server_status/frame.rs#L235)

```sh
unshare --mount --propagation private sh -eu <<'SH'
d=$(mktemp -d)
trap 'umount "$d" 2>/dev/null || true; rmdir "$d"' EXIT
mount -t tmpfs 'audit 10 2 8 20% prefix' "$d"
LC_ALL=C df -P -k "$d"
SH
```

实测 `df` 输出如下。将这一行放入采集帧并交给现有 Rust 解析器。

```text
audit 10 2 8 20% prefix    16356700     0  16356700       0% /tmp/tmp.EvDezQInLp
```

```powershell
Copy-Item target/m4-1-c/m4_review_df_source.rs crates/capstan-core/tests/
try {
    cargo test -p capstan-core --test m4_review_df_source -- --nocapture
} finally {
    Remove-Item -LiteralPath crates/capstan-core/tests/m4_review_df_source.rs
}
```

探针断言失败，退出码 101。预期挂载点为 `/tmp/tmp.EvDezQInLp`，总量和已用字节为 `16749260800 / 0`。实际挂载点为 `prefix    16356700     0  16356700       0% /tmp/tmp.EvDezQInLp`，总量和已用字节为 `10240 / 2048`。

## 加固记录

- P2。shell 或 SFTP 打开 session 被服务器拒绝，且状态 exec 可能占用名额时，通知采集让位，再重试打开一次。有空余名额时，采集继续运行。采集主动让位后重新建立差分基线，服务器拒绝采集重开时使用状态栏既有的不可用和重试流程。经维护者确认，SFTP 入口接入同一打开逻辑。
- P3。`df` 解析要求容量列后的挂载点是绝对路径，并且整行只有一种满足条件的切分。回归覆盖原始数字列源名、带空格的挂载点，以及有两种合法切分的行。
- 进程内 russh 回归覆盖两种名额情况。限制为两个 session 时，状态采集运行期间能打开第二个 shell，采集恢复并暂停后也能初始化 SFTP。限制为三个 session 时，新 shell 使用空余名额，采集继续输出。
