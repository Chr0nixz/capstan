# M4-4 交付记录

Windows Hello 的 Passport KSP 解锁、可选 sidecar 和 UI 接线已实现。根据 [M4-4-C 独立复核](M4-4-C.md)，已加固陈旧 Vault 实例停用 Hello 的冲突处理，以及恢复旧备份后的失效 enrollment 清理和提示。Vault 主文件格式未改变，sidecar 额外保存加密 KEK slot 的扩展已获维护者批准；真实 Hello 手势仍待设备验收。本阶段未修改 `PLAN.md`。

## 修改内容

- `capstan-vault` 定义 `vault-hello.cwh` 有界二进制 sidecar，绑定 Vault 文件标识；Passport KSP 保护随机 wrapping key，sidecar 用 XChaCha20-Poly1305 包裹 DEK。sidecar 不参与 `.cbak` 导出或恢复备份轮换，创建和替换使用原子写入，停用与失效清理在验证后删除。
- 按维护者批准的扩展，sidecar 另含在 DEK 下独立认证的 KEK slot。修改主密码时先暂存旧、新 KEK，再替换 Vault；中断在替换前后都能通过 Hello 解锁，且最多保留两个 slot。
- Windows 原生桥接只使用 Microsoft Passport KSP 的 RSA-2048 非导出解密密钥，要求 mandatory authentication，并在解密前拒绝静默私钥操作；不使用 DPAPI 或软件密钥回退。
- Core、Tauri 和 UI 接入启用、Hello 解锁、停用、错误回退及失效清理。启用需重新验证当前主密码；取消、暂时不可用或失败不会改写 Vault。失效 sidecar 只在主密码解锁成功后清理。
- 停用 Hello 时，在 Vault 文件锁内先核对磁盘内容摘要与实例缓存；其他实例更新 Vault 后，陈旧实例返回 `vault_conflict` 并保留 sidecar 和 Passport 密钥。
- 主密码认证成功的恢复流程与普通密码解锁共用失效清理。恢复早于现有 KEK slot 的备份后，会移除不兼容 sidecar 并设置提示，可以直接改主密码。错误恢复密码保留所有文件；清理失败只提示需要处理，不阻断已认证的恢复会话。
- 更新 `VAULT-FORMAT.md`、原生补丁说明及 M4 fixture，记录 sidecar 格式、错误码和安全边界。

## 已知风险

- Passport KSP 的密钥策略、每次解锁是否都触发新手势，以及 PIN/生物识别取消行为尚未在维护者设备验证。
- 停用时若 KSP 删除密钥失败，sidecar 仍会移除以确保主密码回退；设备上可能留下无法被本应用使用的孤立密钥。
- 目前未做真实桌面窗口的视觉/辅助技术验收；DOM 测试不覆盖 WebView、Windows 安全提示和实际焦点恢复。
- sidecar 无法删除时，恢复会话仍可用并显示需要清理的提示；修改主密码前仍需恢复 sidecar 路径的正常访问。

## 未决问题

- 维护者设备验收：启用时重新输入主密码并批准 Hello；锁定后分别用 PIN/生物识别解锁；取消提示后改用主密码；修改主密码后 Hello 与新主密码仍可用、旧主密码失效；停用后只可用主密码。
- 在便携数据迁移到另一台设备或用户后，确认 Hello 失败回退到主密码，成功解锁后提示并清除失效 sidecar，Vault 数据不变。

## 手测清单

1. 在安全设置启用 Hello，确认先验证当前主密码并出现 Windows PIN/生物识别提示；取消一次后确认 Vault 和原 sidecar 状态不变。
2. 锁定后连续两次使用 Hello 解锁，确认每次都要求新的用户手势；取消后使用主密码解锁。
3. 修改主密码，确认 Hello 解锁和新主密码均可用，旧主密码不能解锁主 Vault。
4. 停用 Hello 并重启应用，确认解锁界面不再提供 Hello，只能使用主密码。
5. 在另一 Windows 用户或设备上打开便携数据，确认主密码可用；Hello 失效只在主密码解锁后清理，Vault 与备份内容保持完整。
6. 连续修改两次主密码，再恢复最初密码的备份。先输入错误恢复密码确认没有清理；正确恢复后应提示 Hello 失效，并能立即改主密码和用新密码解锁。
