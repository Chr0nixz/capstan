## 2026-10-29 首审记录

以下保留首审时的失败证据与命令，C1–C4 的当前状态以本文开头的复审结果为准。

2026-10-29 首审暂不通过：发现 2 项 P1、1 项 P2 实现问题，以及 1 项 P2 模板契约偏差。当时的自动测试未覆盖这些问题。

依据：`AGENTS.md`、`PLAN.md` §4.10、§5–6、`M3.md`、`M3-0-B.md` 的接口约定和 `M3-2-B.md`。独立检查了 Vault 校验/事务/备份、Core 与 Tauri 接线、模板、片段发送、命令面板、主题及相关测试。以下结果均为本轮实际运行，未沿用 B 的通过记录。

### C1 · P1：开发模式下从命令面板运行片段会重复发送（复审已关闭）

位置：`ui/src/snippets/SnippetManager.tsx:66–73`，应用入口 `ui/src/main.tsx:14–17`。

请求片段通过 mount effect 消费。`onRequestConsumed()` 更新父组件状态，不能同步阻止 StrictMode 对同一 effect 的再次执行；无变量片段会两次进入 `finishRun()` 和 `onRun()`。输入队列接受两次独立请求，不会替用户去重。

复现：开发模式 `pnpm tauri dev`，保存模板 `echo review`、开启自动回车，从关闭的片段面板出发，按 `Ctrl+Shift+P` 选择该片段一次。独立 App 探针使用真实片段面板、路由与目的 FIFO，替换终端为记录字节的 endpoint，实际收到：

```text
C1 writes [ 'echo review\r', 'echo review\r' ]
expected 1 call, received 2
```

自动复现命令见下文公共探针，单项可给 Vitest 增加 `-t 'C1:'`。

影响是一次用户操作可执行两次命令。此现象限定于 React 开发构建的 StrictMode effect 重放；未包裹 StrictMode 的对照仅收到一次，不能据此声称生产构建也必然重复。仓库开发入口明确启用了 StrictMode，开发运行中的真实 SSH 命令仍会受影响。

预期：同一运行请求只消费一次；补覆盖实际应用入口的回归测试，不能靠关闭 StrictMode 规避。

### C2 · P2：片段广播部分失败时，失败目标被面板隐藏（复审已关闭）

位置：`ui/src/App.tsx:435–446`、`:1140`、`:1156–1173`。

发送结果写入 App 的 `error`/`notice`，但公共消息仅在 `!sheet` 时渲染。片段面板没有接收这些消息；`onRun` 又丢弃异步结果，SnippetManager 内部的 `error` 无法获得投递失败。

复现：两个已选广播窗格，一个 endpoint 成功，另一个返回 `{code: 'session_closed'}`；运行不附加回车的 `echo review`。实际成功/失败 endpoint 各调用一次，面板仍打开，页面无失败提示或失败目标：

```text
C2 accepted/rejected/alerts 1 1 []
C2 error visible after close true
```

自动复现使用公共探针的 `-t 'C2:'`。关闭片段面板后才出现失败信息，确认结果已产生但未展示。队列满、全部目标失败和空广播目标等写入同一公共消息的路径也存在相同展示缺口。

预期：片段面板打开时即可看到失败目标与不自动重放的提示。当前探针确认没有自动重放；风险是用户在看不到结果时再次点击，导致已成功目标重复执行。

### C3 · P1：输入法组合中的 Enter 会直接执行命令面板动作（复审已关闭）

位置：`ui/src/commands/CommandPalette.tsx:33–41`。

键盘处理只判断 `event.key === 'Enter'`，未检查原生事件的组合状态。输入法确认候选字的 Enter 因而进入 `choose(activeIndex)`，关闭面板并执行动作；选中无变量且自动回车的片段时会直接发到终端。

复现：搜索到上述 `Review command` 片段后，向真实 App 命令面板搜索框派发：

```typescript
new KeyboardEvent('keydown', {
  key: 'Enter', isComposing: true, bubbles: true, cancelable: true,
})
```

公共探针 `-t 'C3:'` 的实际结果为：

```text
C3 composing Enter writes [ 'echo review\r' ]
expected zero calls, received 1
```

探针没有使用 StrictMode，故此问题不依赖 C1 的开发模式重放。预期组合期间 Enter 仅用于输入法，用户明确选择动作后才能执行。事件级复现已确认；Windows 中文输入法与 WebView2 的实机操作仍需维护者验证。

### C4 · P2：文档中的中文变量语法被拒绝（复审已关闭）

位置：`ui/src/snippets/template.ts:3`；保存/运行校验在 `SnippetManager.tsx:47`、`:78`。

`PLAN.md` §4.10 与 M3 契约写明 `{{变量}}` / `{{变量:默认值}}`，没有限定 ASCII 标识符。实现正则只接受 `[A-Za-z_][A-Za-z0-9_]*`，因此中文界面按文档输入的变量无法保存或运行。

公共探针 `-t 'C4:'` 使用 `echo {{目录:/tmp}}`，实际：

```text
isValidSnippetTemplate(...) = false
templateVariables(...) = []
```

预期按文档识别 `目录`，默认值为 `/tmp`。若产品确实只支持 ASCII 名称，应先由维护者确认这项语法限制并同步契约和提示，不能把未记录的限制视为已验收行为。
