# 更新与恢复

当前源码未配置生产更新公钥，更新功能显示不可用。维护者提供公钥、配置受保护 secret 并完成真实升级验收后才能启用。

## 使用

- 设置 → 桌面 → 软件更新，默认手动检查。可选启动时检查，每 24 小时最多一次；检查时间单独保存在数据目录的 `update-check.json`，不改变 Vault。
- 仅接受比当前版本高的稳定版本、`windows-x86_64` 平台和本仓库 Releases 的 NSIS 安装包。清单 ≤ 64 KiB、说明 ≤ 16 KiB、安装包 ≤ 200 MiB。
- 发布说明按纯文本显示。下载暂存后验证包签名与签名绑定的版本，再交给 passive 模式的 NSIS；确认安装后正常结束会话、设置写入和文件工作流。
- 存在活动会话或传输时额外确认；交接安装器前再次检查。远程编辑仍打开时先结束编辑，避免丢失未回传内容。
- 下载可取消。网络、大小、签名或版本校验失败会清理暂存文件，保留现有程序与数据，可重试。
- 便携版只提示新版本，不调用安装器。手动从 [GitHub Releases](https://github.com/Chr0nixz/capstan/releases) 下载便携包，退出程序后替换程序和 `runtime/`，保留完整 `data/`。

## 签名与发布

1. 维护者在可信设备运行 `pnpm -C ui tauri signer generate -w <安全目录>/capstan.key`，妥善离线备份私钥和口令。agent 不生成生产密钥。
2. 将生成的 `.pub` 文件内容写入 `src-tauri/tauri.conf.json` 的 `plugins.updater.pubkey`。保留 `requireSignedVersion: true`，不放宽 TLS 或下载地址策略。
3. 在 GitHub 建立受保护的 `release` Environment，限制正式 tag 并配置所需审核。其 secret 为 `TAURI_SIGNING_PRIVATE_KEY`（私钥文件的完整编码内容）与 `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`。不使用仓库级 secret 向验证作业传递私钥。
4. 分支、PR 和手动演练仍构建未签名包。正式 tag 的受保护发布作业只对已经验证并校验 SHA-256 的安装包运行 `tauri signer sign --app-version <版本>`。
5. `scripts/release.py` 用公钥和 OpenSSL 验证 minisign 的包签名、全局签名与版本绑定，再生成、复核 `.sig` 和 `latest.json`。上传后核对全部资产的 GitHub SHA-256，再公开草稿。

`SHA256SUMS.txt` 包含安装包和便携包。更新清单包含安装包 URL、签名和大小；客户端再次验签。安装包目前没有 Windows Authenticode 签名，SmartScreen 提示与更新包签名是不同机制。实现依据见 [Tauri updater 文档](https://v2.tauri.app/plugin/updater/)。

## 密钥失窃、丢失或轮换

立即停止签名发布并撤销泄露的 secret。更新信任不能由未签名清单里的新公钥替换；维护者须通过独立可信渠道发布需要手动安装、内置新公钥的版本。旧客户端不静默接受换钥，私钥丢失时也采用这条流程。

## 安装失败

NSIS 更新前把安装目录复制到同级 `<安装目录>.capstan-update-backup`。复制失败时在覆盖程序前终止；已有恢复目录时拒绝覆盖。安装失败或取消触发恢复，恢复副本保留供人工处理。

覆盖前记录本次 payload 中原先不存在的受管文件和父目录。回滚逐文件恢复旧备份，字节已一致的文件跳过写入；单个文件受阻仍继续恢复其余文件，并报告恢复不完整、保留备份。随后清除记录中的新增文件及新增空目录，包括 NSIS 生成的卸载程序。原有同名文件、原有空目录和非受管用户文件保留，目录不会递归删除。独立内嵌回滚脚本不依赖提交校验器仍在。

安装器内嵌构建时生成的程序与全部资源 SHA-256 清单。提交前由 Windows PowerShell 5.1 逐文件核对实际安装内容，再次生成卸载程序并立即检查写入结果；写入被拒、文件缺失/篡改、校验器不能执行或校验不通过，都不得提交或删除备份。校验和卸载程序写入均成功后才清理副本。覆盖前 PowerShell 不可用会终止更新；写入后校验或恢复脚本失效时，保留备份人工恢复。

隔离脚本的 8 个场景覆盖真实 `File` 与卸载程序写入被占用、模板统计操作清除错误标志、同长度篡改、校验器缺失、正常写入，以及新增文件/目录清理和用户路径保留；另检查恢复与旧程序启动。它不等于生产签名版本之间的完整升级；断电或强制终止安装器也无法执行失败回调。

失败后先退出 Capstan，保留 `%APPDATA%\Capstan`、当前安装目录和恢复副本。检查副本中有完整旧程序与 `runtime/`。自动恢复未完成时，仅覆盖复制可能残留新增文件：可将副本恢复到干净目录，或依据本次包与备份核对、清理新增的受管文件，再恢复旧文件；也可从可信 Releases 下载此前安装包、核对 SHA-256 后在干净目录重新安装。保留并单独迁移原安装目录中的用户文件，不要整目录删除。确认旧版正常运行后再删除恢复副本。不要删除 Vault、`settings.json` 或传输恢复文件，不要用旧格式构建覆盖新 Vault。

安装器无法启动时，不调用 Tauri 的提前清理，不清空窗口或应用资源；错误提示与再次更新仍可用。交接前已按确认结束的会话不会恢复，重新启动当前程序后可重新连接。更新从不回放终端输入或写入 Vault。隔离 SDK 测试验证了资源保留与连续两次启动拒绝，真实 WebView2 窗口可见性仍需手测。
